## 1. The question

Where does the DA-mode engagement suffix land, across reply shapes x DA mode x C3 flag configurations, and which placement rule removes the dangling ' — worth going further here.' from a bare abstain without altering any surface the defect did not touch?

The suffix (`_SUFFIX` in `webapp/da_mode_drives_chat.py`, appended last to the answer at `webapp/server.py` ~7597-7602 on both main return paths) rides every focus/arousal reply in DA focus mode. Since the C3 topic-locked phasic-DA topic-stop faculty went ON by default (merge 41d76bdbe, 2026-11-01), a repeated topic's follow-up question is dropped by the topic-stop organ, so the suffix now trails a bare abstain: 'I don't know about that. — worth going further here.' — punctuation that promises going further on a reply that declines to. The OFF arm already appends the suffix after the follow-up question ('... about alone? — worth going further here.'). The verify-go panel (`research/findings/2026-11-01-c3-flip-gate-RESULT.md`, 'What changes for a user', lines 44-55) called this a property of the suffix PLACEMENT, not of the flip, and filed it as its own defect.

## 3. The biology it follows

Dopamine/SNc (the record's own anchors: Albin-DeLong-Penney Go/NoGo; Gerfen and Surmeier 2011) is an approach/invigoration state — a 'go, explore, expend effort' bias — not a discourse plan. The suffix is its honest FUNCTIONAL expression at the surface ('my DA-mode read says engaged, so the reply is forthcoming'), never a phenomenal claim.

Discourse-level turn design is a separate layer: a reply offers (content, a follow-up question) or declines (abstain). The conflict in #277 is between a Go neurochemical state and a turn whose own actions all say stop: the moat/BG speak-vs-abstain gate output NoGo ('I don't know about that.'), and — since C3 — the topic-stop organ's per-topic depressing slices say this topic's ASK channel is spent (no question appended). The suffix string 'worth going further here' is not merely a state read-out; its literal semantics are a PROMISE of furtherness, and after the question is dropped there is nothing in the turn to go further to.

So what does a dopaminergic 'go explore' signal mean when the turn declines to engage? Two functional readings, both inside the honesty boundary:

- (a) **State-with-compatible-carrier.** The engagement state is real and should modulate the decline itself — an engaged abstain offers an avenue (in this system the avenue IS the curiosity follow-up question, which the topic-stop faculty owns). When the brain's own stop signal removes the avenue, the state has no honest discourse carrier, and the mouth must withhold the promise (the `da_drives` trace still records focus — no claim that engagement vanished).
- (b) **Turn-design marker.** The suffix is a discourse device whose felicity condition is that some offer exists (content or question); when none does, the marker is infelicitous regardless of state.

Both readings make the promise conditional on an offer; they differ in WHO computes the condition — the brain's own signals (the abstain verdict, the topic-stop organ's read, the ask decision) or the mouth's string structure (does the assembled reply contain the question). This is the biology question the lever choice answers, and it must be answered with a DECLARED host step, not one that silently appears.

## 4. Levers on the defect (grounded in the record reads — the PRE-MAP lever space: hypotheses, not designs; no candidate is designed or chosen until S1's map exists, which §6 enforces)

**L1 — host reply-shape suppression.** Condition the suffix on the reply shape using the brain's own reads (`abstained` plus question presence), never by parsing reply text.
- For: the congruence gate's Declared host step (research/biology/affective-marker-abstention-congruence-gate.md) — gate BEFORE composition on brain-computed reads (`abstained` + the ask decision's boolean/trace, never a parse of the rendered reply). NOT the S6 precedent: S6 is the NAMED HOST SHORTCUT (a host string-edit on an already-composed reply) that the congruence gate replaced, so L1 must cite this pattern and not S6. Smallest host step. HONEST DECLARATION (supersedes the earlier 'SNc-only' claim): L1 amends the 8-19 'suffix present IFF focus/arousal' invariant, and its topic-stop dependence is INDIRECT — question presence flows through the topic-stop organ and the host ask threshold (C3 RESULT: the ask's last step is still host arithmetic), so a topic-stop lesion changes L1 placement too; only L3 makes that dependence direct. L1's named boundary debt: gating on the ask decision's host output.
- Against / trap: a bare `abstained` condition is TOO BROAD — it would also strip the suffix from the OFF-arm surface '... about alone? — worth going further here.' (an abstain WITH a question), which the panel did not flag. The condition must be shape-exact: abstain AND no offer. It also AMENDS the 8-19 invariant to 'suffix present IFF engaged AND the reply carries an offer' — the amendment must be recorded, never drifted.
- Boundary test: acceptable only if it adds no host shortcut deciding cognition (it re-times an existing sanctioned mouth string) and no host read of reply text.

**L2 — suffix-vs-follow-up ordering/attachment.** Two variants:
- *L2-reorder* (the suffix before the question): does NOT touch the dangling case at all — a bare abstain has nothing to reorder against — so it is insufficient for #277; it would only reshuffle the OFF arm ('... about alone?' before vs after the suffix), a byte-identity ripple on a surface the panel did not flag. Predicted: cosmetic-only; bank it.
- *L2-attach* (the suffix rides the question carrier): bind the suffix to the follow-up question's carrier so both are appended or withheld together. Removes the dangling by construction in EVERY configuration (including L=0, where the shared-pool ask threshold can drop the question too — #277 likely predates C3 and was merely rarer before the flip). Leaves answered-turn surfaces untouched (scope: ABSTAIN turns only — applied to every turn it would strip the suffix from answered turns carrying no question, contradicting this sentence; restricted to abstains it is extensionally near-identical to L1-exact, so B1's byte-identity is expected by definition and the real choice is implementation boundary debt). Its ride, however, follows the host string assembly implementing the ask decision, whose last step is still host arithmetic (C3 RESULT: 'decides: unchanged'), so the suffix inherits that declared host step; a topic-stop lesion changes the suffix only indirectly, through question presence.

**L3 — topic-stop gating (integration-first).** Let the C3 topic-stop organ's neural read decide BOTH whether the question is asked and whether the suffix rides: one signal, one reply effect; a lesion of topic-stop would then change the suffix too (slice recovery -> per-topic memory gone -> question returns -> suffix returns). That lesion-visible coupling is exactly the integration-first property the mission rewards.
- Against / traps: (i) `decide()` runs only on abstains and only when L is on — with `BRAIN_CURIOSITY_TOPIC_STOP=0` there is no organ and no signal, so L3 needs a defined fallback that ALSO covers L=0 threshold-dropped questions, or #277 stays open in that config; (ii) the suffix gains a SECOND neural dependency (DA-mode x topic-stop) — defensible ('the offer follows the stop signal') but it must be declared, and the 8-19 claim 'the suffix's lesion route is SNc' becomes 'SNc and topic-stop'; (iii) it couples the engagement mouth to a curiosity organ — one brain, no new module (it reuses the existing organ), but the suffix's meaning becomes conjunctive (engaged AND not-stopped), which is a semantic choice, not a given.

**Discriminating cell.** L2-attach and L3 are observationally identical whenever question presence equals the organ's applied decision, and DIVERGE exactly where the ask's final host arithmetic disagrees with the organ trace (the threshold step is still host, per the C3 RESULT). The probe must capture the topic-stop trace AND question presence on every abstain so this cell is visible.

**Decision rule (applied AFTER Step 1's readings, not now).** Choose the minimal rule that (1) removes every dangling instance in the probe map, (2) leaves answered and abstain+question surfaces byte-identical unless an intentional, recorded change says otherwise, (3) adds no host read of reply text and no host cognition decision, (4) names its declared host step and its amendment to the 8-19 invariant. If L1-exact and L2-attach replay byte-identically over the whole map, the choice is boundary debt, not behavior — prefer the one with the smaller declared host step and record the other as banked method. L3 is preferred only if the probe shows the divergence cell is real AND biology reading (a) is taken (one signal, one reply effect), with its L=0 fallback designed and named.

## 7. Matrix, seeds, cell counts

Axes: reply shape {bare abstain, abstain + follow-up question, answered recall} x DA mode {rest, focus, arousal} x C3 config {unset (L+P on), L=0, L=1 with P=0} for the three defect shapes, plus ONE content-free rest-control cell per seed (the L-lesion config is NOT in S1 — S3 owns it). Content-free handling: one naturally-resting control cell per seed (C3 acts only on abstains); induced focus/arousal content-free cells are excluded — per 8-19 the SNc afferent sets the mode regardless of content, so they would CARRY the suffix and are not defect cells; A6 names this hole. Shape forcing: bare abstain via a repeated topic (C3 ON) or a sub-threshold topic (L=0); abstain+question via a first abstain on a novel topic; answered recall via a taught fact; rest via content-free turns. Cell count: (3 shapes x 3 modes x 3 configs) + 1 rest-control = 28 per seed; 3 dev seeds (7, 1, 2) = 84 S1 cells, plus about 36 S3 re-run cells (L-lesion, only if L3 survives Table B). Dev seeds only (7 and 1-15) — gate seeds 42/43/44/100/101/102 are untouched, so no generalization claim is possible or made (six-seed claims are a CLAUDE-owned gate's job).

S1 is 84 cells (21-42 min aggregate); S2 under 1 min (pure replay); S3 adds about 36 cells (9-18 min). Total budget: at most 3 h of pool time — comfortably 'a few hours'. Lane: the pool (`research/queue/pool.queue`) on numpy CPU, per RULING compute-placement (the C3 battery ran its cells pool 28 / workstation 20 the same way); each runner invocation batches at most 16 cells (16 x 30 s = 8 min < the 10-min dev-host bound); the workstation is the fallback if the pool is saturated. No GPU; check `tools/mem_ok.sh` per runbook section 5 before the batch.
