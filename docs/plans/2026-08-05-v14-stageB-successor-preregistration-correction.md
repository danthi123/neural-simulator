# Stage B successor preregistration correction

The first successor manifest draft, schema
`v14-snr-stageB-sobol-candidate-manifest-v2`, was committed but never
materialized or executed. Independent review found that its overlap guard used
candidate digests containing candidate IDs. A changed ID could therefore hide
an already-consumed parameter vector. Campaign materialization also did not
regenerate the successor partition, and the screen aggregator accepted only the
original manifest schema.

The draft is superseded by
`research/specs/v14_snr_stageB_sobol_candidates_v3.json`. V3 adds a full
design-identity digest to every row, compares canonical parameter vectors
against the consumed predecessor, and is exactly regenerated by generation,
campaign, and aggregation paths. The old V2 schema is explicitly rejected.

No candidate from either successor file had been compiled, simulated, scored,
or used to change the search space when this correction was filed.

GPU batch-width selection is separately preregistered in
`research/specs/v14_snr_stageB_v3_batch_width_benchmark.json`. It uses only the
consumed V1 candidates and cannot inspect the corrected successor partition.
