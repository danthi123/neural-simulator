# Phase 1.3 Hippocampus -> cortex consolidation -- detailed design

**Date:** 2026-05-06
**Status:** Design (ready for implementation when Phase 1.4 result is in).
**Master plan ref:** `docs/plans/2026-05-06-MASTER-PLAN-main-then-pathF.md`
section "Phase 1.3 -- Hippocampus -> cortex consolidation closed loop".

---

## Why detailed design now

Phase 1.3 closes the loop on Buzsaki/McClelland complementary-learning-systems
theory: hippocampus learns fast, cortex learns slow, sleep transfers
hippo -> cortex. This is the BIOLOGY-GROUNDED mitigation for catastrophic
forgetting if Phase 1.4 reveals it. Pre-staging the design lets us
implement immediately when the result lands.

---

## What infrastructure already exists (g11_bg_runner)

Cluster D v1 provides ec, dg, dg_pv_basket, ca3, ca1 regions and the
trisynaptic loop (ec -> dg -> ca3 -> ca1, plus ec -> ca1 direct bypass).
Cluster D v2 adds SWR-gated CA3 plasticity (`ca3_swr_burst` gate) for
sleep-replay sharpening of the recurrent autoassociator.

**Gap for consolidation:**
- ca1 has NO pathway to motor cortex (only to `sensor_place_readout`)
- ca1 has NO pathway to language cortex
- No "sleep" loop that drives replay AND opens cortex plasticity

## What's missing in `build_biological_brain_regions`

The bio_three_factor / Phase 1.4 architecture (`text_minimal_isolation.
build_biological_brain_regions`) doesn't include hippocampus AT ALL.
Phase 1.3 needs to either:

- **Option A:** Extend `build_biological_brain_regions` with optional
  hippocampus regions (parameter `enable_hippocampus_consolidation: bool`)
- **Option B:** Use g11_bg_runner with `--enable-cluster-d-hippocampus
  --enable-cluster-d-v2-swr` and add the missing ca1 -> language /
  motor cortex pathways
- **Option C:** Build new combined architecture for consolidation
  (lift cluster_d code into bio_three_factor)

**Choose:** A. Cleanest. The Phase 1.4 architecture is already validated
for word-action binding; adding optional hippo to the SAME builder
preserves all the eval infrastructure.

## Sleep loop: training-time logic

In `run_three_factor` (or a new `run_three_factor_with_sleep`):

```
for episode in episodes:
    # AWAKE phase: encode events -> hippocampus
    bridge.set_plasticity_gate("lang_to_ec", 1.0)
    bridge.set_plasticity_gate("ec_to_dg", 1.0)
    bridge.set_plasticity_gate("dg_to_ca3", 1.0)
    bridge.set_plasticity_gate("ec_to_ca1", 1.0)
    bridge.set_plasticity_gate("ca3_to_ca1", 1.0)
    bridge.set_plasticity_gate("ca3_swr_burst", 0.0)   # awake = no recurrent learning
    bridge.set_plasticity_gate("ca1_to_motor", 0.0)    # awake = no consolidation
    bridge.set_plasticity_gate("ca1_to_lang_out", 0.0)
    bridge.set_plasticity_gate("language_input_to_motor", 1.0)  # also keep direct path

    # ... do N training events ...

    # SLEEP phase (every M episodes): replay -> cortex
    if episode % consolidation_interval == 0:
        bridge.set_plasticity_gate("lang_to_ec", 0.0)        # no encoding
        bridge.set_plasticity_gate("ec_to_dg", 0.0)
        bridge.set_plasticity_gate("ec_to_ca1", 0.0)
        bridge.set_plasticity_gate("ca3_swr_burst", 1.0)     # ripple-burst plasticity ON
        bridge.set_plasticity_gate("ca3_to_ca1", 1.0)        # rebuilt forward
        bridge.set_plasticity_gate("ca1_to_motor", 1.0)      # consolidation ON
        bridge.set_plasticity_gate("ca1_to_lang_out", 1.0)
        bridge.set_plasticity_gate("language_input_to_motor", 0.0)  # freeze direct path
                                                                      # so cortex can't
                                                                      # also be retrained
                                                                      # by direct route

        # Drive CA3 with SWR bursts (~150Hz, 100ms windows)
        for ripple in num_ripple_events:
            # Inject pseudorandom CA3 patterns
            # (in v1: just background OU noise, let attractors emerge)
            for step in 100:  # 100ms at dt=1ms
                bridge._run_one_simulation_step()
            # Pause between ripples
            for step in 50:
                bridge._run_one_simulation_step()
```

### Why "freeze direct path" during sleep is critical

Without it, sleep replay would compete with the language_input -> motor
direct pathway. Both would be plastic; the strong direct pathway would
dominate updates and CA1 -> motor wouldn't get enough plasticity to
consolidate. By freezing direct during sleep, we force the cortex
plasticity to use only the CA1 input.

## Eval: post-sleep retention

After full training arc (awake + sleep cycles):

1. **Test 1: full architecture standard W->A eval**
   - Drive language_input, freeze all plasticity, read motor.
   - Should match Phase 1.4 baseline (~25-30% accuracy).

2. **Test 2: hippocampus-OFF eval (the consolidation proof)**
   - Set lang->ec plasticity gate to 0 AND zero out CA3+CA1 firing
     (force their `cp_external_input_current` to a strong negative
     value, or zero their excitability)
   - Drive language_input, read motor.
   - **PASS criterion:** if cortex truly learned via consolidation,
     accuracy should remain >= 50% of Test 1. If hippo-OFF drops to
     chance, it means cortex never consolidated and was always relying
     on hippocampal route.

3. **Test 3: forgetting + sleep recovery**
   - Train Phase A (primaries), sleep cycle, eval -> baseline accuracy
   - Train Phase B (synonyms), sleep cycle, eval -> retention test
   - Without sleep, Phase 1.4 measures retention. WITH sleep, retention
     should improve. **PASS criterion:** retention >= 80% (vs. master
     plan threshold).

## Decision: ec input source

Currently the design assumes `language_input -> ec`. But during nav
training (Tier 2.2), the more biological source is sensory cortex
(visual/place cells) -> ec. The dual-source design:

- **Tier 1 / 1.4 / 2.1 (text-only):** language_input -> ec
- **Tier 2.2+ (with visual cortex):** language_input AND visual_cortex -> ec
- **Tier 2.3+ (with PFC):** add PFC -> ec for working-memory anchoring

For Phase 1.3 first-pass: use language_input -> ec only (matches Phase
1.4 architecture).

## Wall-clock budget

- Awake phase: same as Phase 1.4 training (~19 min for 800 events)
- Sleep phase: 200 SWR events x 150 ms each = 30 sec compute (very cheap)
- Total per seed: ~20 min (sleep adds <2 min overhead)
- 6-seed validation: ~2 hours total at parallel=2

Same scale as Phase 1.4. Cheap to validate.

## Risks + mitigations

| Risk | Mitigation |
|---|---|
| Sleep replay doesn't drive cortex strongly enough | Increase replay drive amplitude; tune CA1->motor weight |
| Cortex develops conflicting patterns vs. direct path | Freeze `language_input_to_motor` during sleep (per design) |
| Replay erases existing cortex knowledge | Open ONLY ca1->motor during sleep; freeze cortex internal recurrence and direct path |
| 800 awake events insufficient to encode in CA3 | Tune: lang->ec weight, ec->dg weight, dg->ca3 weight |
| CA3 pattern separation insufficient | Tune dg_pv_basket FFi strength to enforce sparsity (Marr 1971 argues for ~5% activity) |

## Decision: when to implement

Per Phase 1.4 decision tree (`docs/plans/2026-05-06-Phase-1.4-decision-tree.md`):

- **Branch A (retention >= 80%):** Phase 1.3 NOT urgent; can defer to Phase 2.
  Implement only if user wants fuller biology demonstration.
- **Branch B (retention 50-80%):** Phase 1.3 IS the natural mitigation;
  implement immediately as Phase 1.4b.
- **Branch C (retention < 50%):** Phase 1.3 + simpler mitigations
  (heterosynaptic LTD, replay-interleaving) all needed.

For Branch B / C: this design is ready. Start implementation when 6-seed
1.4 validation completes.
