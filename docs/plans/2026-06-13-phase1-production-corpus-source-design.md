# Phase 1 production corpus-source design — how the 32 real bridges get their within-cluster graded structure (the brain-based-only decision before the corpus is coded)

**Date:** 2026-06-13. **Status:** DESIGN NOTE (design-before-build; no code, gated behind the 32-bridge fan-out result + owner review). **Context:** the production vocab spec `research/runners/g20_vocab_spec_2048.py` is DONE (commit `882c0e04`; 32 semantic clusters of 64 = 2,048 concepts). The next Phase-1 piece (build plan piece ii, `docs/plans/2026-06-11-semantically-structured-cortex-BUILD-PLAN.md`; sharding design §1.3, `docs/plans/2026-06-12-phase1-sharding-and-fanout-design.md`) is the **per-bridge corpus** that induces the within-cluster co-occurrence the learn consumes. This note resolves the one load-bearing decision in that piece **before** writing the generator, because the obvious reuse path bakes in a shortcut.

## The decision
The learned-graded cortex produces each bridge's graded codes by LEARNING from a within-bridge co-occurrence corpus (the spiking-Hebbian `LearnedAssocGraph` → homeostatic `W` → divnorm read-out). The graded similarity the bridge ends up with is whatever the corpus's co-occurrence structure encodes. **So "what is the production corpus's within-cluster structure?" is the decision that determines whether the cortex's similarity is MEANINGFUL (cat∼dog because they really are alike) or ARBITRARY (cat∼whatever-the-corpus-grouped-it-with).**

## Why the obvious reuse is a shortcut
The de-risk + the in-flight 32-bridge fan-out build their corpus with `build_toy_cooccurrence(n_sub, per_sub, …)` (`learned_graded_embedding_derisk_probe.py:132`): it makes `n_sub` synthetic sub-clusters of `per_sub` synthetic members (`hub{c}`, `c{c}_m{m}`), ties cluster-mates together ONLY via a shared synthetic hub (the second-order cat∼dog case), and emits `S_true` = the cluster-block matrix. The learn is **name-agnostic** — it consumes the index-pair fact list, so the WORDS are just labels. **The graded structure comes entirely from the synthetic sub-cluster assignment, not from any real property of the words.** That is exactly right for the de-risk (it tests the MECHANISM — can a brain-based learn recover a known graded structure, and does cross-bridge composition + the moat survive — on a controlled `S_true`). But reusing it verbatim over the real 2,048 vocab would assign the 64 real words to sub-clusters **arbitrarily** (by index), so "mammal #3 ∼ mammal #19" would hold because they landed in the same synthetic bucket, NOT because they are semantically similar. The cortex's headline capability — generalization-in-conversation ("what does a dog eat?" → meat via cat∼dog) — would then generalize along **meaningless** lines. Under the project's BRAIN-BASED-ONLY standard this is a shortcut: the similarity is GIVEN by an arbitrary assignment, not learned from real experience (the same class of caveat as "codes GIVEN by sparse encoding" in the 320 flat-distinct work, and the composer-as-idealization note). **It must not be the production corpus.**

## The three options

**Option A — synthetic-arbitrary (the de-risk corpus, verbatim over real words). ✗ REJECTED.** Cheapest (zero new work) but the within-bridge similarity is arbitrary → generalization is meaningless → a BRAIN-BASED-ONLY shortcut. Fine for the fan-out de-risk (which only needs *a* known `S_true`), wrong for production.

**Option B — a curated within-cluster SUB-taxonomy. ✓ RECOMMENDED for the immediate production corpus.** Extend the curation one level: for each of the 32 clusters, group its 64 words into real sub-categories (e.g. `mammals` → {pets: dog/cat/…, farm: cow/pig/sheep/…, big_cats: lion/tiger/leopard/…, sea: whale/dolphin/seal/otter/…, rodents: mouse/rat/squirrel/…, …}). Feed those sub-groups (not arbitrary indices) as the sub-clusters + use the sub-category as the shared hub. Then `S_true` (and the resulting graded similarity) is **semantically meaningful** — lion∼tiger because they really are both big cats; the cat∼dog second-order generalization is real (shared "pets" hub). This REUSES the validated `build_toy_cooccurrence`/`learn_W_homeostatic`/divnorm mechanism unchanged (only the sub-cluster *assignment* becomes curated instead of synthetic) and the per-bridge G1/G2 gate validates it directly. Cost: curate 32 × ~8 sub-groups of ~8 = ~256 sub-groups (the natural one-level-deeper extension of the vocab spec; a bounded authoring task with the same global-uniqueness discipline). **Honest caveat:** the similarity is still hand-CURATED, not learned-from-raw-experience — a principled stepping-stone (the curation encodes the real semantic structure the spiking learn then reproduces IN SPIKES + generalizes from), not the end state. This mirrors how the vocab spec's taxonomic curation "guarantees taxonomic similarity" (sharding design §1.3 layer 1); Option B is layer 2 (make them co-occur) done honestly.

**Option C — real distributional co-occurrence. ✓✓ the genuine target (follow-on).** Derive the within-cluster co-occurrence from REAL experience — the agent's own SVO-fact KB co-occurrence (the build plan's stated intent, piece ii line 42–44) and/or a real text corpus (Tiny Shakespeare / a public word-co-occurrence resource), so the graded structure is LEARNED from distributional statistics (Garagnani-Pulvermüller 2018; Hultén 2021 — the precedented brain-based distributional-semantics route). This is the most brain-based (the learn extracts the structure from real experience rather than from a curated block matrix). **Risk (the build plan's own, piece i/ii):** biological Hebbian learning is weaker than backprop-on-big-data, and the agent's KB may be too sparse over 2,048 concepts to induce graded-ENOUGH structure (the "~4 orders too small" gap the project hit in Phase 2.3a) → realistic partial = a `BOUNDARY_weak_graded`. So C is the genuine-distributional target, with B as the validated stepping-stone that de-risks the rest of the pipeline (sharding → train → conversational matrix) on meaningful similarity while C's data-strength question is settled separately.

## Recommendation
**Build the production corpus via Option B (curated semantic sub-taxonomy) — explicitly NOT Option A.** It gives meaningful within-bridge generalization, reuses the fully-validated corpus/learn/read-out mechanism, is validated per-bridge by the existing G1/G2 gate (Pearson(sim, S_true) ≥ 0.7 + within>between margin + held-out-neighbour generalization ≥ 0.7), and is the natural one-level-deeper extension of the vocab spec. Pursue **Option C (real KB/text co-occurrence) as the genuine-distributional follow-on** the build plan ultimately wants, with its honest data-strength risk de-risked on its own (does a brain-based learn over the real KB/corpus recover the curated B sub-taxonomy's S_true? — a clean cheap-first falsification that also tells us whether C can replace B).

## How this is gated
This decision feeds the corpus generator + the 32-cortex-bridge train, both of which are **downstream of the in-flight 32-bridge fan-out de-risk** (the deepest Phase-1 risk: cross-bridge SNR + the no-confab moat at 32-bridge fan-out). On fan-out GO → author the Option-B sub-taxonomy + corpus generator → per-bridge G1/G2 gate → the 32-cortex-bridge train. On fan-out NEGATIVE → the sharding/routing reshapes first, but this corpus-source decision is unchanged (the within-cluster structure is a per-bridge property, independent of cross-bridge routing). The multi-day production train itself remains the owner-gated commitment. No `sim/` edits. No banking — the honest call is to reject the cheap arbitrary-synthetic reuse and curate meaningful structure (or learn it from real co-occurrence), per BRAIN-BASED-ONLY.
