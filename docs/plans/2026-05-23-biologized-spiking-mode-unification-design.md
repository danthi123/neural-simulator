# Biologized spiking theta-gamma mode-unification: design — implement order-bearing AND order-invariant readout from one spiking-substrate encoded code on the project's validated substrate

## Status

Design, pre-registered. The biologized spiking implementation of the
theta-gamma mode-unification mechanism on the project's validated
substrate. Justified by the algebra-PASS + capacity-envelope
characterisation: the FHRR algebra supports unified bidirectional
readout at every tested cell, including at noise levels matching the
substrate's raw spiking coefficient of variation. The build follows
the FHRR-biologization arc's pattern: reuse validated infrastructure
byte-unchanged; add the minimal genuinely-new components (the
gamma-slot position phasors and the two readout decoders); test
both readouts on the same spiking-substrate encoding against the
frozen 0.80 bar.

## Background and motivation

The owner's 2026-05-19 scientific reframe named theta-gamma mode-
unification as "the key catalog-documented interconnection the
project never built" and load-bearing for the conversational path.
The cheap-first algebra probe (2026-05-23) demonstrated the FHRR
algebra supports unified bidirectional readout at multi-seed 1.000.
The characterisation (2026-05-23) demonstrated the algebra survives
substrate-realistic noise levels (std=1.6 matching the substrate's
raw spiking CV) at usable accuracy. The biologized spiking
implementation is the natural next pre-registered step.

The FHRR-biologization arc already established the biology-faithful
spiking implementation of phase-coded composition on the project's
substrate: resonate-and-fire neurons (Frady & Sommer 2019) for
bind/unbind/bundle; threshold-phasor attractor clean-up with a
separate familiarity gate; common-mode-removed substrate activity
as the grounded symbol input. The trained-substrate runner +
K_VOCAB=16 recipe established the substrate side (trained G.20
sparse bridge; activity capture; symbol derivation).

The mode-unification implementation EXTENDS that established
pipeline by adding sequence encoding (item k at gamma-slot position
k within one theta cycle) and the two complementary readouts
(per-slot order-bearing; marginal-sum order-invariant).

## The build, structurally

What is reused, byte-unchanged:

- The validated trained-substrate runner (`trained_substrate` from
  `vocabulary_scaling_run_trained.py`) for building + training each
  bridge.
- The substrate's per-concept activity capture
  (`capture_concept_activity` from `vocabulary_scaling_run.py`).
- The biologized grounded-composition pipeline's components:
  `_ground_symbols` (mean-centred activity -> phasor); the
  resonate-and-fire FHRR (`ResonateFireFHRR`); the annealed-
  threshold attractor (`ResonateFireTPAM`); the separate
  familiarity gate.
- The frozen 0.80 compositional bar.
- The K=16 PASS recipe (M_OBS=16, K_VOCAB=16, K_RECOG=8, N_TRIALS=
  200, multi-seed 42/43/44).
- The validated G.20 sparse substrate at 32-64 concepts per bridge.

What is genuinely new (the minimal additions):

- **A per-seed deterministic set of N_GAMMA_SLOTS = 7 gamma-slot
  position phasors** generated by the same mechanism the existing
  pipeline uses to derive concept symbols (the same FHRR
  primitives). Pure-function helper; unit-tested; no biology
  decisions involved at this step (the positions are FHRR
  primitives, not substrate states).
- **Sequence encoding via gamma-slot binding**: for an ordered
  sequence (item_1, ..., item_K), encode C = bundle_k
  [bind(grounded_symbol(item_k), position_k)]. Uses the same
  resonate-and-fire bind/bundle the FHRR-biologization arc
  validated.
- **Two readout decoders on the SAME encoded C**:
  - ORDER-BEARING: for each slot k=1..K, compute unbind(C,
    position_k) and run it through the attractor + familiarity
    gate to recover item_k. Sequence the recovered items by slot
    index. Match the encoded K-tuple exactly for PASS at one
    trial.
  - ORDER-INVARIANT: for each candidate item w in the
    vocabulary, compute score(w) = sum_k similarity(unbind(C,
    position_k), grounded_symbol(w)). Take the top-K items by
    score, sorted by index. Match the encoded set exactly for
    PASS at one trial.
- **A new runner that orchestrates sequence-encode + both-readouts
  per trial per load per seed**, aggregates per-bridge per-load
  multi-seed, applies the pre-registered verdict.

{2, 3, 5} (within the 7-slot gamma ceiling). Same FHRR phasor

PRE-REGISTERED reading:
- **PASS**: BOTH order-bearing AND order-invariant multi-seed-mean
  >= 0.80 at every load {2, 3, 5} on the one tested bridge. The
  biologized spiking implementation realises the catalog-documented
  Lisman-Idiart N.16 mechanism on the project's substrate. Subject

## Soundness considerations

A PASS at this build must survive these adversarial checks before
being claimed:

1. **No answer leak across the orchestration.** The recognised
   concept (output of the substrate's nearest-match recognition,
   not the true label) must be the only handle that names which
   symbol is bound at any slot. The encoding loop must use the
   true sequence (it has to — encoding's job is to encode), but
   the DECODING loop must NEVER access the true sequence or the
   true items; only the readouts' outputs (the recovered K-tuple
   for order-bearing; the top-K item indices for order-invariant)
   are compared to the encoded items for scoring.

2. **The biologized pipeline is reused byte-unchanged.** The
   adversarial reviewer must verify the runner imports
   `ResonateFireFHRR`, `ResonateFireTPAM`, `_ground_symbols` (or
   its equivalent), `phases_to_spikes`, `make_deriver` from their
   validated modules without modification, and that those modules
   are not touched in the build's `git diff`.

3. **Gamma-slot positions are FIXED per seed**, generated
   deterministically; no per-trial regeneration; the same 7
   positions across all trials per (bridge, seed, load).

4. **The substrate is genuinely trained** (the K=16 PASS substrate
   recipe, byte-unchanged) -- the runner doesn't bypass training.
   The captured activity density per bridge must sit in the
   substrate's normal regime (0.04-0.06 for the 160-ensemble
   tier; 0.09-0.11 for the 64-concept tier).

5. **Both readouts on the SAME C.** The reviewer must verify the
   encoded code C is computed once per trial and both readouts
   operate on the same C. (If they operated on different codes,
   the unification claim would be vacuous.)

6. **The frozen 0.80 bar is unchanged.** Imported from
   `vocabulary_scaling_run`; never redefined; verdict logic uses
   `mean_int < BAR` exactly.

7. **No automatic differentiation.** Grep.

8. **The per-slot decoder genuinely uses unbind(C, position_k) as
   its sole input** -- not the true position-conditioned symbol
   (which would be an oracle).

9. **The marginal-sum decoder genuinely scores every vocabulary
   item against the full sequence** -- not just the encoded items
   (which would be an oracle).

10. **The capacity envelope is respected**: K <= 7 (the gamma-slot
    ceiling); per-bridge vocabulary <= 256 (the characterisation
    upper bound where both readouts cleared); noise at the
    substrate's natural level (no artificial noise added).

## Implementation outline (TDD plan to follow separately)

Task 0: grounding pin (test that frozen bar + K=16 recipe + 7 gamma
slots + 32 concepts per bridge + multi-seed + loads are all
unchanged from the K=16 PASS / characterisation contracts; module-
exists check on the new runner red until Task 2).

Task 1: a small `gamma_slot_positions(seed, n_slots, n_dim)` helper
that returns N_GAMMA_SLOTS=7 fixed deterministic complex-phasor
positions. Pure function; unit-tested (shape, dtype, determinism,
pairwise near-orthogonality with random vocab phasors at the same
n_dim).

Task 2: the runner
`research/findings/raw/biologized_spiking_mode_unification_runner.py`.
Focused orchestration: build + train one bridge (using
`train_substrate` byte-unchanged); capture activity at M_OBS=16;
derive per-concept grounded symbol via `_ground_symbols`; per
trial: sample an ordered K-item sequence; encode C =
sum_k bind(grounded_symbol(item_k), position_k); run BOTH readouts
on the same C; tally per-load accuracies; aggregate multi-seed;
verdict.

Task 3: soundness tests (load-bearing structural properties: gamma-
slot positions are FIXED per seed; both readouts share the same C;
the recognition pathway is preserved as the only handle that names
which symbol is bound; the pipeline's reused modules are not
modified).

Task 4: dedicated adversarial review BEFORE the decisive run (10
exploit-class checks per the soundness considerations above).

Task 5: controller-only decisive GPU run on one bridge (bridgeA_nouns
at 32 concepts; multi-seed 42/43/44; loads {2, 3, 5}; ~35-60 min
per seed for the substrate build + train + capture; pipeline runs
are cheap CPU after capture is cached). Mandatory anti-cheat smell-
test; honest propagation either way.

After Task 5 PASS: a fresh dedicated adversarial review before the
capability_status pillar claim. Then optionally extend to the
5-bridge ensemble as a separate larger arc (~5x the GPU time, kill-
safe per-bridge per-seed cache).

## Wall-clock estimate

Per bridge per seed: build + train + capture roughly 35 minutes (the
160-ensemble characterisation's per-bridge-seed cost). 1 bridge × 3
seeds = ~2 hours GPU. The pipeline composition runs are cheap CPU
after the capture is cached.

This is a focused single-runner GPU commitment of ~2 hours, not the
multi-week scale I initially framed. The mode-unification only adds
the gamma-slot phasors + two readout decoders + a new orchestration
loop on top of the existing K=16 PASS recipe; the SUBSTANTIVE work
is the build code and the adversarial review, not the GPU time.
This is similar in scope to the trained-substrate runner build, not
to a multi-week new-architecture build.

The 5-bridge extension (if the 1-bridge result PASSes) would be
~10 hours GPU (5 bridges × 3 seeds × ~35 min), matching the
160-ensemble's commitment.

## Honest scope

A focused build on a validated foundation. Whatever the verdict, it
is one further test in a continuing line; the algebra-PASS and the
capacity-envelope characterisation stand. A PASS on one bridge
justifies extending across the 5-bridge ensemble and ultimately
connecting mode-unification to generative replay (the broader-
horizon arc the owner named). A NEGATIVE on one bridge is itself a
clean biology-translatable finding: the algebra-PASS does not
straightforwardly transfer to the biologized substrate even at
algebra-friendly noise levels, and the failure mode sharpens which
biological component would need refinement.

Frozen 0.80 bar never tuned; reuse-by-import only; no protected,
frozen, or moat module modified; no automatic differentiation; the
no-confab moat must remain 7/7 green throughout. The standing
oracle-adjacency caveats from the FHRR-biologization arc apply
unchanged: the mode-unification uses the substrate's stable concept
identities as the symbols (substrate-grounded, with the same
caveats; the pattern-grounded NEGATIVE established that pure
substrate-pattern symbols don't compose, so the substrate's
activity-derived mean-centred symbols are the load-bearing
biological signal).
