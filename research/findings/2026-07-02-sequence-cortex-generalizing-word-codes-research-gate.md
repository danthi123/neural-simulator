# Research gate: GENERALIZING word codes for the emergent on-bridge HTM Temporal-Memory sequence cortex (2026-07-02)

**Type:** mandated deep-research gate BEFORE a new-mechanism sub-direction (per CLAUDE.md "research gate", trigger (d) new mechanism class + (c) blocks the stated communication goal). Read-only; no `sim/` edit; no build. Deliverable = this doc + a named cheapest next de-risk.

**The direction:** the rung-4 emergent HTM Temporal-Memory (TM) sequence cortex is a word-level language model on the real spiking `SimulationBridge` — it PREDICTS the next word from high-order context (`2026-07-02-emerge15-word-sequence-lm-GO.md`) and GENERATES autoregressively from a cue (`2026-07-02-emerge16-word-generation-GO.md`), both 6-seed GO, no `sim/` edit. The gap: it MEMORIZES exact sequences and cannot GENERALIZE across similar words (no notion that dog≈cat), because **each word = one column** (a disjoint block of `nE` cells); words are orthogonal. Give it similarity-structured word codes that generalize WITHOUT breaking the HTM-TM dynamics.

## 1. ISOLATE the true residual — pinned to exact bytes

### How the substrate represents a word (read from the runners)
- `OnBridgeLearner._col(c) = range(c*nE, (c+1)*nE)` (`_emerge14_stageC_onbridge_learning_derisk.py:151-152`): word `c` owns a **disjoint** block of `nE` cells. Word codes are orthogonal by construction — there is zero cross-word cell sharing.
- Within a column, the k_win-cell **winner SDR** is chosen by allocation (`train_sequence`, lines 192-217): a PRIMED subset if predicted, else a MATCH set (`_match_count` ≥ learn_th), else ALLOCATE onto the freshest cells (`_committed_count`). The SAME word in a DIFFERENT prior context gets a DIFFERENT winner SDR within its column — this is the HTM context-specific disjoint-context SDR self-organization (the thing R1 made scale to n_seq=8, `2026-07-02-emerge14-onbridge-nseq-scaling-R1-surpassed-GO.md`).
- **Two levels already exist, cleanly separated:** the WORD identity = *which column* (`cell // nE`, read in `_emerge16` `generate_from_cue`: `col_votes = Counter(i // nE for i in predictive)`); the CONTEXT = *which cells within the column*. Generalization is a property of the WORD/column level; the context SDR is the cell level.

### The exact residual (small and precise)
The residual is **the word→active-set ENCODING**, and ONLY that. Concretely, three sub-pieces:

1. **The encoding itself** — replace "word `c` → the single disjoint block `[c*nE, (c+1)*nE)`" with "word `c` → a set of active cells that OVERLAP for similar words." Everything else (the coincidence prediction, the three-term `sim/` kernel, the `_committed`/`_match` allocation, the excitability-replay generation) is unchanged bytes.

2. **Does overlap break allocation?** — the load-bearing risk (§3 risk box). The allocation self-organizes disjoint CONTEXT SDRs. If two similar words' codes literally share the SAME cells, the coincidence recurrence into those shared cells is ambiguous. The reconciliation (validated by canonical HTM, §2) is: **overlap at the INPUT/column level, keep the context SDR disjoint at the CELL level** — i.e. similar words activate overlapping SETS OF COLUMNS (a word = a union of shared micro-columns), and within each column the TM still allocates disjoint context cells. The generalization lives in the *shared columns*, the disambiguation in the *within-column context cells*. This is exactly the HTM Spatial-Pooler (overlapping SDRs for similar inputs) vs Temporal-Memory (disjoint cells per context) division of labour.

3. **What proves it** — anti-cheats that a memorizer cannot pass: (a) **held-out similar word** — train on "dog chased the ball home"; at test present a NOVEL-but-similar subject "wolf" (code overlaps "dog"); a memorizer predicts nothing / chance; generalization predicts the dog-branch by shared-column transfer. (b) **transfer across similar contexts** — a transition learned for one word predicts the analogous continuation for a similar word. (c) The standing suite: dAP-LESION collapse, permuted/derangement (shuffle the similarity structure → generalization vanishes but exact-recall survives = the transfer is from *structure*, not a bias), no-teacher, multi-seed.

### What is ALREADY SHIPPED (isolates the residual to "wire an existing code set in")
- **Similarity-structured word codes exist and generalize:** the stream-cortex PPMI codes — `research/findings/raw/_phaseB_stream_codes_320_seed42.npy`, a **dense (320, 300) float64** array (verified this session), learned by on-bridge Hebbian co-occurrence, dog≈cat cosine +0.7–+0.87, between-category +0.05–+0.14, **held-out generalization 0.86** (chance 0.125), permuted −0.009 (`2026-06-15-on-bridge-hebbian-co-occurrence-learning-mechanism-GO.md`; `2026-06-15-off-diagonal-red-herring-ppmi-local-normalization-reaches-host.md`). A neural on-bridge read version exists too (`_phaseB_stream_codes_320_neural_seed{42,43,44}.npy`).
- **The taxonomy** `research/runners/stream_taxonomy_320.py` (`TAXONOMY_40x8`) gives ground-truth semantic categories for the held-out/derangement anti-cheats.
- **Top-K sparsification of the dense PPMI code preserves overlap∝similarity** (verified this session, K=30 of N=300): most-similar pair cos 0.618 → 15/30 shared active cells; median pair cos 0.015 → 4/30; least-similar cos −0.48 → 0/30; **corr(cosine, active-overlap) = +0.48 over 400 random pairs**. So a dense PPMI vector can be turned into a K-of-N active set where similar words share active cells — directly the HTM input format.
- **NOT the right source: the G.20 `generate_sparse_patterns` / `concept_pool_sparse_distributed` codes are FLAT-DISTINCT** — independently random K-of-N (`concept_pool_sparse_distributed.py:137-152`, docstring: "Patterns overlap by chance; expected overlap ≈ K²/N ≈ 5 for K=100, N=2000"), NO similarity by design; `2026-06-02-full-320-flat-distinct-composition-*.md` explicitly names them "flat-distinct … GIVEN by the orthogonal/Kanerva sparse encoding" (mean between-concept cosine 0.045). They are the DISTINCTNESS substrate, not a generalizing one. Do not use them for this.

## 2. REFRAME via real biology + the project's own prior work (cited)

### How cortex gets generalizing word representations
- **Sparse distributed codes where overlap IS similarity (the canonical HTM/NLP answer).** Numenta/Cortical.io **Semantic Folding**: a word is a sparse binary "semantic fingerprint"; the *overlap of active bits encodes semantic similarity* — "words with similar meanings will have similar word-vectors … systems based on SDRs automatically generalize based on semantic similarity" (Cortical.io Semantic Folding; Semantic Folding — Wikipedia; De Sousa Webber white paper). This is precisely "similar words share active cells" and is the theory *designed to feed HTM-TM* (the fingerprint is "directly usable by HTM networks").
- **The Spatial-Pooler vs Temporal-Memory division of labour (the reconciliation of the overlap-vs-allocation risk).** In canonical HTM the **Spatial Pooler** produces *proportional-overlap* SDRs for similar inputs ("similar input patterns produce SDRs with proportional overlaps in their active bits, aiding generalization"; Cui-Ahmad-Hawkins 2017, *The HTM Spatial Pooler*, Front. Comput. Neurosci. 11:111). The **Temporal Memory** then activates *disjoint cells per temporal context* within those columns (Ahmad-Hawkins 2016, *Properties of SDRs*). So the field's own answer is: **overlap at the column/input level; disjoint at the within-column context-cell level** — exactly the split the project's substrate already has (`cell // nE` = column, cell-in-column = context).
- **SDR overlap ~ similarity, quantitatively.** Ahmad-Hawkins: with large N and small K, overlap of active bits is a robust, noise-tolerant similarity metric; a shared-column union is unambiguous with vanishing false-match probability (Ahmad & Hawkins 2016).
- **Marr-Albus expansion recoding — the cerebellar biology of "overlapping but separable" (catalog F.12).** Catalog `references/feature-catalog.md` F.12 "Codon representation": overlapping mossy-fibre inputs map to *overlapping but proportionally less-overlapping* granule-cell subsets — "pattern overlap X scales as (W/L)^R, so codons separate similar inputs geometrically" (Marr 1969 §3; Albus 1971 §IV.A). This is the biological statement that a good code keeps similar things overlapping *enough to generalize* but separable *enough to disambiguate* — the exact knob (K, N, threshold) the sparsified-PPMI encoding tunes.
- **Distributed graded semantic codes (why similar words overlap at all).** Patterson-Lambon Ralph **hub-and-spoke**: the ATL hub integrates modality-specific spokes into modality-invariant conceptual codes with a "graded, distributed overlap where similar concepts share neural substrates" (Patterson & Lambon Ralph 2016; hub-and-spoke white-matter evidence, *Brain* 2020). Huth et al. 2016 (*Nature*) semantic maps: word meaning is a smooth, overlapping distributed cortical code. This is the biological warrant that the PPMI similarity structure (dog≈cat) is the right target, not an artifact.

### The project's own machinery says "reuse, don't reinvent"
- The generalizing codes are **already built and validated**: the stream/PPMI cortex (learned from the conversation stream on the real bridge, `corr(M,C)=+0.885`, generalizes held-out 0.86) and the whole **generalization arc** (`_genfrontier_*`, `2026-06-16-generalization-*`): similarity from the visual hierarchy (`_genfrontier_optionB_visual_similarity`, within-cat 0.86 vs between 0.08, RSA r=0.99), cross-modal Hebbian convergence transferring category structure (held-out cat-acc 0.92), NMDA graded propagation making the converged concept SPIKE category-correctly. The decisive project conclusion (CLAUDE.md + `2026-06-15`): **generalization needs feed-forward LOCAL normalization (PPMI) + shared features, NOT cross-neuron decorrelation and NOT the dendritic rewrite.** The sequence cortex is the one place these codes have not yet been dropped in.
- Reframe of the "boundary": this is NOT "the substrate can't generalize" — it is "the sequence cortex is currently fed ORTHOGONAL codes; feed it the project's already-generalizing codes." A wrong-hypothesis check in the same spirit as EMERGE-14 R1 (the n_seq wall was a disguised operating-point bug).

## 3. RANK cheap-first paths (each: mechanism · citation · smallest de-risk · anti-cheats · sim/-edit · overlap-vs-allocation risk)

### ⭐ Path A — sparsify the shipped PPMI codes into overlapping COLUMN-unions; keep within-column context cells disjoint (CHEAPEST, RECOMMENDED)
- **Mechanism.** Give each word a code = the **union of a set of shared micro-columns** it activates, where the micro-column set is the top-K of the word's sparsified PPMI vector, so similar words share micro-columns. Within each shared micro-column, the TM still runs its normal `nE`-cell context allocation (disjoint context SDRs). Word identity is decoded as before by column-vote (`Counter(cell // nE)` generalizes to a union vote over the word's columns). This is literally Spatial-Pooler-over-PPMI feeding the existing Temporal-Memory.
- **Citation.** Semantic Folding (overlap = similarity, HTM-ready); Cui-Ahmad-Hawkins 2017 (SP proportional-overlap SDRs); Ahmad-Hawkins 2016 (overlap-as-similarity, disjoint TM cells); project PPMI codes `2026-06-15-*` + Marr-Albus F.12.
- **Smallest de-risk (named in §4).** Reuse-by-import: load `_phaseB_stream_codes_320_seed42.npy`, top-K each word to a small set of shared columns (K≈4–8 columns from a shared pool of ~40–80 columns), feed those as the per-word active COLUMN set into a lightly-generalized `OnBridgeLearner` (a `word2cols` map instead of the single `_col`). Tiny corpus: two families of similar subjects (dog/wolf/fox = canines share columns; cat/lynx = felines share columns) each with a family-branch; train on a SUBSET, test the HELD-OUT family member.
- **Anti-cheats.** (1) held-out similar word (train dog, test wolf → predict the canine branch, ≫ chance); (2) permuted/derangement (shuffle which words are "similar" → exact-recall of trained words survives but held-out transfer collapses to chance = the transfer is from the *similarity structure*, not leakage); (3) dAP-LESION → collapse; (4) FLAT-code control (feed the same words as ORTHOGONAL columns = the current EMERGE-16 encoding → held-out transfer at chance, positively isolating that the OVERLAP is what buys generalization); (5) no-teacher; (6) multi-seed 6.
- **`sim/` edit?** **NO.** Purely a runner-side `word2cols` encoding + a generalized `_col`→`_cols` and the column-vote read-out. The coincidence kernel, prediction, allocation are untouched.
- **Overlap-vs-allocation risk — LOW, and this is the whole point.** Overlap lives at the COLUMN level (shared micro-columns); the allocation's disjoint-context self-organization runs UNCHANGED per column at the CELL level. The R1 allocation (the fragile piece) is not asked to disambiguate similar words — the shared columns intentionally do NOT disambiguate them (that IS the generalization); disambiguation of *context* still happens within each column exactly as validated. The one thing to watch: a shared column now has MORE distinct contexts to hold (n_similar_words × n_contexts) → may need more `nE` cells/column (the exact R1 lever: `nE ≥ k_win × n_contexts_per_column`). This is a known, cheap capacity dial, not a new mechanism.

### Path B — similarity-graded INPUT layer → a distribution over disjoint columns (keep columns orthogonal)
- **Mechanism.** Keep the existing one-word-one-disjoint-column TM, but prepend a fixed similarity-graded projection (the sparsified-PPMI code → a soft distribution over columns) so a novel word partially activates the columns of its neighbours. Generalization is then a *read-out-time* union of neighbour predictions.
- **Citation.** HTM Spatial Pooler as a separate layer feeding TM (Cui-Ahmad-Hawkins 2017); union-of-predictions (Ahmad-Hawkins 2016). Project: the fixed grounded-projection pattern used in step-3 compose (`2026-06-16-navigate-to-compose-then-answer.md`).
- **Smallest de-risk.** Same corpus as A; the novel word's input = its PPMI neighbours' columns weighted by cosine; test held-out transfer.
- **Anti-cheats.** Same suite as A.
- **`sim/` edit?** **NO** (a fixed input projection, runner-side).
- **Overlap-vs-allocation risk — LOW but WEAKER generalization than A.** Columns stay orthogonal so allocation is byte-identical (zero risk), but the generalization is only as good as the input soft-mixing (a novel word never gets its OWN context cells; it borrows neighbours'). Likely a partial-generalization ceiling below A. Good as a zero-risk fallback / positive control if A's shared-column allocation misbehaves.

### Path C — two-stage lexical→sequence cortex (a learned Spatial Pooler in front of the TM)
- **Mechanism.** A learned lexical layer (the stream/PPMI cortex itself, or a proximal-segment Spatial Pooler learned on the corpus) produces the overlapping SDR; the HTM-TM sequence layer consumes it. This is the full canonical two-region HTM.
- **Citation.** Cui-Ahmad-Hawkins 2017 (the SP is a learned online layer); Semantic Folding; project stream cortex `2026-06-15-*` (the SP-equivalent is already learned on-bridge).
- **Smallest de-risk.** Larger — wire the stream-cortex population output as the TM input on ONE bridge, corpus-driven; multi-seed held-out.
- **Anti-cheats.** Same suite + a lesion of the lexical layer.
- **`sim/` edit?** Probably NO (two co-resident regions, reuse-by-import), but more integration surface than A/B.
- **Overlap-vs-allocation risk — MEDIUM.** The learned SP output overlap is not hand-controlled, so the shared-column capacity (nE) must absorb whatever overlap the SP produces; needs the R1 capacity dial and possibly the R2 multi-segment cell-efficiency lever if cells get scarce. Higher cost, higher fidelity; the *destination*, not the first step.

### Path D (deferred, characterized — NOT next) — R2 multi-segment cells for cell-efficiency under heavy shared-column load
- If A/C run the shared columns out of cells (many similar words × many contexts per shared column), the R2 `segment_id` OR-over-segments lever (Hawkins-Ahmad 2016 cell reuse; catalog F.12/Poirazi-Mel) lets one cell hold multiple contexts. Already characterized as a ranked-second, guarded, default-off, numpy-de-risk-first lever (`2026-07-02-emerge14-onbridge-nseq-scaling-R1-surpassed-GO.md` R2). It is a cell-EFFICIENCY axis, only needed if the capacity dial (more `nE`) is exhausted — do NOT pre-emptively build it.

**Ranking:** A ≫ B > C ≫ D. A is the cheapest, most-of-the-value, zero-`sim/`-edit, reuse-by-import path with the risk correctly parked at the column level.

## Key overlap-vs-allocation finding (the load-bearing risk, resolved)
The allocation's disjoint-context self-organization (the fragile R1 piece) is **NOT** threatened by code overlap, because the correct architecture — mandated independently by canonical HTM (Spatial Pooler overlaps at the column/input level; Temporal Memory keeps cells disjoint per context) — puts the OVERLAP at the COLUMN level and keeps the CONTEXT SDR disjoint at the CELL level within each column. The project's substrate already encodes exactly these two levels (`cell // nE` = column identity; cell-within-column = context). So similar words share COLUMNS (→ generalization) while the TM still allocates disjoint CONTEXT CELLS within each shared column (→ disambiguation, unchanged). The only knock-on is a capacity dial (a shared column holds more contexts → needs more `nE` cells, the exact R1 lever), not a mechanism break. This makes Path A a code-encoding change over the validated learner, with the risk parked where it is cheap.
