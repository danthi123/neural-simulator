Multiplicative weight decay on synapses originating from the key's
language_input neurons. Backend-aware (CuPy + NumPy). Returns full
schema with mean_weight_pre/post and estimated_retention.

## Live smoke confirmation

Both demo and webapp endpoints verified end-to-end:

```bash
$ curl -s -X POST http://localhost:8765/api/llm-chat -d '{
    "lineage": "main", "mode": "synonym",
    "message": "Remember that my favorite is north."
}'
# {"response":"Got it. I'll remember: favorite = north.",
#  "tool_calls":[{"name":"memory_store",
#                 "result_summary":"bound -> motor_N (conf=inf)"}],
#  "conversation_length":3, "n_turns":1}
```

Stack: MockLLM regex → ToolCall(memory_store) → LLMMemoryOrchestrator
→ BridgeMemory.store("favorite", "north", n_events=200) →
chat_repl.learn_word_pairing → 200 co-firing events on the real
12K-neuron synonym bridge → BridgeLineage.save() → JSON response.

## Known limitation (worth following up)

New-vocab bindings against synonym-scale bridges still recall weakly.
Binding "favorite" → north then recalling "favorite" returns motor_S
or motor_E top-1 (not motor_N) at 200 events. The issue:

- `vocab_to_drive_pattern("favorite")` activates a random subset of
  language_input neurons (top ~10% by Gaussian embedding)
- Those neurons have NEAR-ZERO weight to motor_N pre-binding
- 200 events of co-firing add weight, but the existing random
  weights in the recall path swamp the signal at 12K neurons

The Tier 2.1 breakthrough used 400 events per direction during PRIMARY
training (with motor teacher current also active). In-vivo bind via
`learn_word_pairing` adds 200 events with motor teacher, but the
recall path has no teacher — it depends purely on the
language_input → motor_X synapses.

Possible follow-ups:
- Higher n_events default (400-800) for new-vocab binds
- Different binding rule (e.g. eligibility-trace-based with longer
  consolidation window)
- Decoder fine-tune step after each in-vivo bind (1-2 events with
  language_input drive + softmax loss on motor target)

For the demonstrated use case ("remember my favorite is north"), the
MECHANICS work — store succeeds, recall returns ranked results, and
BridgeLineage persists everything. The SCIENCE accuracy is the
follow-up.
