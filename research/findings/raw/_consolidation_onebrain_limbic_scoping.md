## 1. DIAGNOSIS — the gap between `MergedRFComposer` and a co-resident `OneBrainComposer`

### 1.1 What each composer is, precisely

| | `MergedRFComposer` (the current merged default when `co_resident_composer=True`) | `OneBrainComposer` (the proven persistent-loop composer) |
|---|---|---|
| Base | subclass of `RFPhasorComposer` | API-sibling of `RFPhasorComposer`; **owns** an inner `RFPhasorComposer` (`self.comp`) for codes/roles/cleanup-codebook |
| Bridge | runs on the **merged** bridge's `rf` slice (overrides `_resonate`) | builds its OWN `build_coresident_bridge(seed, n_total)` (`one_brain_composer.py:282`); the parser + RF registers + store + cleanup are ALL slices on THAT bridge |
| Fact store | **numpy `self.kb`** (a list of `(fact, composite_phases)`) — phases held on the host | **synaptic** `store_conns` written into the bridge's complex weights (`_write_block` → `cp_rf_w_re/im`), block-major, K=32, register-reset-safe (GAP A GO) |
| Op hand-off | host `to_host(rf_read_phases)` per op (inherited `RFPhasorComposer._resonate`, `:169` — per-op cached bridge) | `persistent_loop=True` → `_dev_rekick_into` keeps the composite ON-substrate between ops (I-1-a byte-identical GO, CYCLE 526) |
| Comprehension | the merged agent's `self.parser.parse(...)` → host `{role:word}` → `composer.store(strings)` | the composer OWNS a `BridgeParser` on slice `[0:P]`; `hear()` reads the parser's role firing (still a host `{role:word}` dict — Route D residual) |
| Cleanup selection | host `np.argmax` (numpy default; spiking-cleanup explicitly BLOCKED in `__init__`, `:1417`) | `enable_spiking_cleanup=True` default → spiking Izhikevich WTA (`_spiking_select`) |
| Cue-match routing | host first-match loop | `integrated_loop=True` → spiking K-way sequencer (`_seq_block`) |
| `encoding_gain_fn` | **does not exist** (RFPhasorComposer stores phases) | consumed by `_write_block` (`:385`) — the limbic write-side hook |

The two are NOT drop-in interchangeable: `OneBrainComposer` is NOT an `RFPhasorComposer` subclass and it builds its own bridge. So "the merged bridge simply USES `OneBrainComposer`" is **not** a one-line constructor swap — but it IS the same KIND of port `MergedRFComposer` already performs.

### 1.2 The precise residual — can the merged bridge USE `OneBrainComposer` on its `rf` slice?

**Yes, by the same mechanism `MergedRFComposer` uses, applied one level up.** `OneBrainComposer` reaches the bridge through exactly TWO surfaces, both of which can be redirected to a slice of the merged bridge:

1. **The bridge handle `self.b`** (`one_brain_composer.py:282`). Today `__init__` calls `build_coresident_bridge(seed, self.n_total, ...)`. To co-reside, `self.b` must instead be the **merged bridge**, and the composer's region layout (`store_base`, `q_base`, `c_base`, `bat_q_base`, …, `n_total`) must be **rebased by the merged `rf` slice base** so every absolute index it writes (`kick[...]`, `store_conns`, the unbind/clean tuple lists) lands inside the merged `rf` region.
2. **The masked RF ops** — every RF call already passes `neuron_mask=self.rf_mask` (`rf_kick`, the resonate loop respects the persisted mask, `_dev_rekick_into` resets the masked trackers). `rf_set_complex_weights` builds the full-`(N,N)` complex CSR (sparse), so a larger N is fine. The inner `self.comp` (`RFPhasorComposer`) is used ONLY for `_to_phasor`/codes/roles/`_local_conj`/`_cleanup_conj` — it NEVER touches a bridge in the read paths (those go through `self.b`), so it stays standalone (no second bridge spun up in the hot path). **Caveat:** `self.comp` DOES lazily build its own per-op bridge for `_spiking_select`'s Izhikevich concept bank (`comp._izh_bank(V)`); that is a small auxiliary cleanup bridge, not a duplicate composer bridge, and is array-disjoint from everything — acceptable (or co-reside it as a later purity item).

**So the consolidation = a new co-resident constructor/subclass for `OneBrainComposer`** (mirror `MergedRFComposer.__init__`): accept `(merged_bridge, rf_base, rf_size)`, set `self.b = merged_bridge`, set `self.rf_mask` over `[rf_base : rf_base+rf_size]`, and **rebase every absolute index by `rf_base`** (the parser slice `[0:P]` also moves into the `rf` region OR — cleaner — the merged bridge's EXISTING `parse_conj`/`parse_role` slices are reused and the composer's own parser is dropped, exactly as `MergedNavConvAgent` already drops the composer's parser and uses the merged parser; see §1.3). The `n_total` the composer needs (`bat_c_base + k_max*cb`, ~tens of thousands of RF registers/cleanup neurons at D=128/V≈16) must be reserved in the merged bridge's `rf` region (raise `rf_D`/`rf_size` so `rf_size ≥ OneBrainComposer.n_total`).

### 1.3 Is it reuse-by-import or new wiring?

**Reuse-by-import with one genuinely-new (small) port + two layout decisions.** Breakdown:

- **NEW (small):** a co-resident `_resonate`-equivalent rebasing of `OneBrainComposer` onto a merged-bridge slice. This is the SAME pattern as `MergedRFComposer._resonate` (`:1429` — shift local→global by `base`, full-N kick, masked `rf_kick`), but `OneBrainComposer` does not funnel everything through a single `_resonate` (it issues `rf_set_complex_weights`/`rf_kick`/`rf_resonate_steps`/`_dev_rekick_into` inline across ~8 methods with ABSOLUTE indices). So the port is: **make every absolute index relative to a `self._rf_base` offset** (a mechanical, contained refactor — `store_base = rf_base + P + …` instead of `P + …`). This is the only real engineering.
- **LAYOUT decision 1 — the parser.** Either (a) move `OneBrainComposer`'s own `BridgeParser` slice into the merged `rf` region (self-contained), or (b) reuse the merged bridge's existing `parse_conj`/`parse_role` slices (the `MergedNavConvAgent` already trains + reads those via `_MergedParserAdapter`) and have the co-resident `OneBrainComposer` DELEGATE comprehension to them (drop its own parser). (b) is cleaner (one parser on the merged bridge, no duplicate) and matches how `MergedNavConvAgent.hear` already works (`:1883` — `self.parser.parse(...)` → `self.composer.store(...)`). Recommend (b): the composer exposes `store()` (resolved roles), the agent's merged parser supplies the roles. (This also keeps the I-5/Route-D synaptic-comprehension question cleanly separate — out of THIS arc's scope.)
- **LAYOUT decision 2 — `n_total` reservation.** The merged `rf` region must be sized to hold the `OneBrainComposer`'s full register/store/cleanup layout. Today `rf_D=128` sizes `rf` as `7*rf_D` (`MergedRFComposer` needs 7 D-blocks). `OneBrainComposer.n_total` is much larger (work registers + K_max store blocks + per-block AND batched Q+cleanup). So `build_merged_nav_conv_bridge` must accept a larger `rf_size` (or a dedicated `onebrain_rf_size`) computed from the `OneBrainComposer` layout formula. Mechanical; appended LAST so all other index bases stay byte-unchanged (the established discipline).
- **REUSE-BY-IMPORT (everything else):** `persistent_loop`/`integrated_loop`/`enable_spiking_cleanup`/`encoding_gain_fn`/`grounded_codes` are existing `OneBrainComposer` kwargs; the agent's `_da_encoding_gain`/`_da_confidence_gate`/`_gated_out` already exist; the byte-identity discipline (`finalize_conv_for_nav_gate`, the per-region homeostasis mask, the masked `rf_kick`) is shipped.

**Net:** NOT new science; ONE contained index-rebasing port + two layout decisions. The persistent loop, the synaptic store, the limbic hook, and the spiking cleanup/sequencer are ALL already built and de-risked GO — this arc makes them co-resident on the merged bridge.
