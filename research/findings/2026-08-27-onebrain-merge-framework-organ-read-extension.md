## How comprehension closed — a FROZEN forward-pass read on the pool slice

Comprehension is a `SpikingRoleCompetition` (Wong-Wang `sel_agent`/`sel_patient` accumulators in mutual
inhibition, driven by installed cue->role validity synapses). Its read DRIVES the semantic cue votes for a
transitive's two nouns, settles the WTA, and reads the firing margin `|agentEv_0 - agentEv_1|` off
`cp_firing_states`. Crucially the cue->role validities are INSTALLED (constants), plasticity is FROZEN (the cue
gates are 0), so the read NEVER mutates a weight — it is a clean deterministic function of the frozen substrate
slice, exactly the closable shape self_schema/d6 have.

The `shared=` seam (additive, byte-identical when None): `SpikingRoleCompetition.__init__` gained `shared=None`;
when a MergedPool is injected it adopts `pool.bridge`, discovers its `sel_*`/`cue_*` index maps from the pool's
`region_manager`, and returns (no own bridge). `_build_comp(shared=pool)` then installs the SAME cue->role
validities on the pool's own edges (overwriting the base-pathway `cue_to_role_init` weights the `wire=True`
per-region-seamed inject regenerated) and freezes the cue gates — deterministic + identical merged-vs-coresident.
`ComprehensionProductionOrgan` gained `shared=None`, uses the pool's settle-to-rest snapshot (`pool.snap`) as its
hard-reset rest (so `_hard_reset` returns EVERY slice to rest — co-residents included, no clobber), and wraps its
calibration + each margin read in `pool.read_isolation("comprehension")`. No new NON-pathway wiring is needed (the
WTA sel<->FS edges + the cue->role edges are all standard `RegionPathway`s regenerated by the pool's wiring
inject), so comprehension needs NO `explicit_wiring_fn`/`post_inject_fn` — only a config + the read plumbing.

Config UNIONs compatibly (no MergeConflict): `enable_nmda` ON (the `sel_*` regions carry per-region
`enable_nmda=True` in the spec, so they join the pool's NMDA mask); every plasticity/noise flag OFF, matching the
frozen pool and agreeing exactly with self_schema/d6 on the shared keys. Homeostasis stays OFF (the frozen-pool
value) and the read runs at the pool's dt=1.0 — the de-risk's declared merge operating point; the read stays
meaningful there (the well/ill margin gap above).

## Honest boundary — unchanged: still the MIGRATION gate, not INTEGRATION

Byte-identity-in-ISOLATION forbids the cross-region interaction that IS the one-brain goal: a pool with zero
cross-synapses is MIGRATED, not INTEGRATED. The co-resident-alone baseline is the pool-built-alone organ on the
superset config, NOT the organ's pre-migration standalone — the claim is co-residence-invariance of the read,
not identity to the un-merged organ (which runs at dt=0.5). Comprehension's dt=1.0/homeostasis-OFF operating point
is a DECLARED reconciliation (the de-risk supports it; the read stays well/ill-separating), not the standalone's
dt=0.5 regime — the byte-identity is merged-vs-coresident at that shared operating point.

## The remaining four organ-read deferrals — now a PRECISE per-organ read-path map

Each was traced end-to-end (production organ + de-risk builder + the live call site). None blocked the batch; each
names the EXACT seam. Registered as data in `onebrain_merge_framework.GROUP_A_ORGANREAD_DEFERRED`.

- `curiosity` — the production read is ALREADY a frozen forward pass (reward-learning forced 0; the spiking-SNc /
  reward critic is BUILT but NEVER exercised by the read, so `enable_stdp`/`enable_reward_modulation` are
  vestigial for it). The ONLY read-load-bearing dependency is the `curiosity` NEUROMODULATOR SUBSYSTEM
  (`enable_neuromodulator_subsystem` + a `from_novelty` rule driving `excitability_drive` on `group:ask` — the ASK
  pool has NO afferent pathway, so it fires only via the modulator). PLUS `enable_ou_process` defaults ON and
  perturbs the ASK read; the global OU RNG is index-order, hence co-residence-DEPENDENT. Seam: enable+register the
  curiosity modulator on the pool (a global-subsystem config seam — verify a `group:ask`-scoped modulator leaves
  every co-resident slice byte-identical) + force OU off (a per-neuron-seeded OU stream would be a `sim/` edit).
  The neuromod subsystem's internals live in `sim/`.
- `source_provenance` — the read is `encode(fact,provenance)+recall(fact)`; the ENCODE mutates `cp_connections` (a
  zero-init episode->prov Hebbian trace, gate `prov_learn`) and runs INLINE in the per-turn answer path on
  FIRST-encounter of a key (`brain_conversational_agent` calls `encode_fact` then `judge_fact` every turn), NOT
  once at build. `recall()` alone is a clean frozen forward pass. `ProvenanceBrain` hardcodes its own bridge (needs
  `shared=`); `recall()` does `cp_external_input_current[:]=0` (would stomp co-residents -> needs read_isolation).
  Its `enable_nmda=False` reconciles via the existing per-region mask (its regions opt OUT); but
  `enable_hebbian_learning=True` is GLOBAL and conflicts with the frozen pool. Seam: move the Hebbian encode to a
  per-region-gated BUILD-time step (recall-only read), OR a global-hebbian toggle with a universal gain-0 freeze of
  every non-prov edge during the encode.
- `prospective_memory` — NOT a single-call drive->settle->read. The faculty holds an intention across an
  a-priori-unbounded number of INDEPENDENT production turns (form -> hold through arbitrary intervening turns ->
  cue); the self-sustaining cortex<->dlpfc attractor + per-neuron SFA trace must persist UNRESET across those
  separate calls (`_reset_dynamics` fires only at a fresh formation), so it cannot be reconstructed from a rest
  snapshot per call. AND the default-ON formation (`form_intention_hebbian`) MUTATES `cp_connections` per FORMATION
  turn. Its config (plastic_internal/pathway plastic=False, `enable_nmda=True`, OU off) IS frozen-pool-compatible
  per-region, and SFA/plateau are host current-injection proxies (per-neuron state, fine). Seam: the hierarchy must
  accept an injected bridge + a STATEFUL multi-turn read protocol, plus (default path) a per-formation-turn
  weight-mutation seam.
- `causal_whatif` — two independent blockers. (1) The read takes a live `RFPhasorComposer` as a per-call argument;
  `_recalled(composer,e)` gates confirmed/confab/answer on EVERY `what_if`/`why` call (the substrate forward-pass
  diagnostics `predicts_D`/`D_rate`/cause ARE composer-independent and would run byte-identically once evt is
  trained, but the emitted ANSWER is 100% composer-load-bearing). (2) `build_forward_model` TRAINS temporal-order
  STDP + phasic-DA (`enable_stdp`+`enable_reward_modulation` ON) at BUILD then freezes; the `wire=True` pool never
  runs that training, so the evt slice would be untrained. Seam: a stub/shared composer surface exposing
  `query_patient` faithfully + a per-region STDP+DA build-time training seam (train the evt slice while the pool
  stays frozen elsewhere).
