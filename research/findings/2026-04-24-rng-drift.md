# RNG Drift — Infrastructure Lockdown

**Date:** 2026-04-24
**Gate:** Session A (pre-G8, biology-neutral)
**Motivating bug:** gamma-oscillations benchmark peak frequency varied 29–135 Hz across same-commit reruns
**Verdict:** **GO** — benchmarks now seeded end-to-end, drift-detector test in CI, baseline values locked

---

## 1. Problem

Two independent failure modes surfaced during G5-G7 work, both traceable to un-seeded RNG paths:

1. **Gamma benchmark intermittent failure.** Peak frequency measured 93, 131, 117, 29, ... Hz across
   same-commit reruns, making it impossible to distinguish "this refactor broke something" from
   "the Poisson realization happened to land in a bad spot." The 100 Hz upper-bound threshold on
   the PASS condition was flipping roughly 40% of the time.

2. **Silent benchmark drift across refactors.** There was no single locked numeric value that
   would fail if someone re-ordered `cp.random.*` calls, added a new random draw somewhere in
   the simulation step, or changed the heterogeneity init order. A regression would show up only
   as "a benchmark started producing different numbers," and only if someone noticed.

Both are reproducibility bugs. For a system that aims to model real biology — where the same
protocol must produce the same result — this is an unacceptable baseline for the research work
above it (G8+ learning experiments).

## 2. Root cause

The simulator has three seed fields in `CoreSimConfig`:

| Field | Controls | Status |
|---|---|---|
| `seed` | Main cp/np/random streams, covers OU noise + heterogeneity via fallthrough | Wired up correctly at `bridge.py:699-704` |
| `heterogeneity_seed` | Parameter-heterogeneity init only, falls back to `seed` if -1 | Wired up at `bridge.py:1138-1141` (save/restore RNG state) |
| `ou_seed` | *Intent*: separate RNG stream for OU noise | **NOT WIRED UP** — see §5 |

Until today, four of five benchmarks in `run_benchmarks.py` were calling `CoreSimConfig()` and
leaving `seed` at its default `-1` (which becomes a fresh epoch-derived seed on every run). Only
`gamma-oscillations` had a recent seed fix (commit `cc71207`); the others were truly non-deterministic
run-to-run.

This was a silent hazard. "Passed at commit X" didn't mean "will pass at commit X on rerun."

## 3. Fix

Three-layer infrastructure change, biology-neutral (no kernel or dynamics changes):

### 3.1 Explicit seeding per benchmark

All five benchmark functions now accept `seed_override: int = 42`. Each sets
`core_cfg.seed = seed_override` before constructing the `SimulationBridge`:

```python
def benchmark_gamma_oscillations(seed_override: int = 42):
    ...
    core_cfg.seed = seed_override
```

Because `heterogeneity_seed` and OU noise both fall through to the main `seed` (OU via shared
`cp.random` stream, heterogeneity via `bridge.py:1138` fallback), setting `seed` is sufficient
for full reproducibility on a given machine/CuPy version.

### 3.2 CLI — `--seed` and `--multi-seed`

```bash
python run_benchmarks.py -b gamma-oscillations                          # seed=42
python run_benchmarks.py -b gamma-oscillations --seed 17                # single seed
python run_benchmarks.py -b gamma-oscillations --multi-seed 42,43,44    # sweep
```

The multi-seed path runs each benchmark N times, accumulates per-seed results, and prints
mean / std / min / max for a curated set of metric keys per benchmark (e.g. `peak_freq_hz`,
`exc_rate_hz`, `gamma_fraction` for gamma; `baseline_hz`, `recovery_late_hz` for homeostasis).
This makes seed-sensitivity visible at a glance.

### 3.3 Drift-detector test

New file: `tests/test_benchmark_drift.py` with three CI-fast tests + one opt-in slow test.

| Test | What it protects | Runtime |
|---|---|---|
| `test_stdp_kernel_exact` | Fused STDP kernel formula (analytical, no RNG) | <0.1 s |
| `test_tiny_seeded_sim_reproducible` | Same seed → identical spike trajectory | ~1 s |
| `test_tiny_seeded_sim_spike_count_in_range` | Locks seed=42 tiny-sim spike count to **170 ± 10** | ~1 s |
| `test_gamma_peak_locked` (opt-in `RUN_SLOW_TESTS=1`) | Locks gamma peak @ seed=42 to **[25, 55] Hz** | ~15 s |

The tiny sim is the primary drift detector: 100 neurons, 200 steps of Izhikevich + OU(mean=50pA),
no plasticity. That's enough to exercise the main RNG stream (OU draws + neuron state init)
without the cost of a full-size benchmark. Any reorder or change in the RNG-consuming code
paths will shift the spike count by far more than ±10.

## 4. Multi-seed baseline measurements

### 4.1 E/I balance (10,000 neurons, 10 s sim)

Extremely stable across seeds. Firing rates reproduce to 3 decimal places; verdict never flips.

| Seed | exc rate (Hz) | inh rate (Hz) | E/I ratio | exc CV(ISI) | inh CV(ISI) | passed |
|------|---------------|---------------|-----------|-------------|-------------|--------|
| 42   | 1.790         | 3.237         | 4.0       | 0.833       | 0.878       | ✓ |
| 43   | 1.782         | 3.214         | 4.0       | 0.812       | 0.835       | ✓ |
| 44   | 1.787         | 3.208         | 4.0       | 0.812       | 0.852       | ✓ |
| **mean** | **1.786** | **3.220**     | **4.0**   | **0.819**   | **0.855**   | **3/3** |
| **std**  | 0.003     | 0.013         | 0.0       | 0.010       | 0.018       |     |

Takeaway: `ei-balance` is an excellent regression target. Seed-to-seed std is under 1% of
the mean. A change that moves exc rate outside [1.75, 1.83] Hz or E/I ratio off 4.0 is
almost certainly a real regression, not RNG noise.

### 4.2 Gamma oscillations (5,000 neurons, 5 s sim)

Highly seed-sensitive. The peak-frequency detector lands in different PSD bumps depending on
which Poisson/OU realization wins. This **is the original motivating bug**: you cannot use
a peak-frequency threshold as a pass/fail gate with un-seeded RNG.

| Seed | peak (Hz) | gamma frac | exc rate (Hz) | inh rate (Hz) | passed |
|------|-----------|------------|---------------|---------------|--------|
| 42   | 38.7      | 0.360      | 1.8           | 3.2           | ✓ (classic gamma) |
| 43   | 59.3      | 0.378      | 1.8           | 3.2           | ✓ (high gamma)    |
| 44   | 105.7     | 0.345      | 1.8           | 3.3           | ✗ (above 100 Hz threshold) |
| **mean** | **67.9** | **0.361** | **1.8**     | **3.23**      | **2/3** |
| **std**  | **28.0** | 0.013      | 0.0           | 0.047         |         |

Takeaway: the firing-rate metrics are reproducible; the peak-frequency metric is not. The 2/3
seeds pass / 1/3 fail split means the historical intermittent failure was not a bug in the
sim — it was a mis-designed pass condition. The `seed=42` default (now locked in the drift
test at [25, 55] Hz) gives a reliable PASS for the health check. A future fix here should
either relax the peak-frequency threshold or switch to a different metric (e.g. gamma-band
power fraction, which is 0.345-0.378 and stable).

Biology note: seed 44's 105.7 Hz peak is not non-physical — high gamma (60-150 Hz, sometimes
called "fast gamma" or "epsilon band") is a real cortical regime, seen in hippocampal
sharp-wave ripples and during intense attentional load. The benchmark's 100 Hz upper bound
predates the `CORTEX_GAMMA_FS_NETWORK` profile (which was tuned for strong PING), so the
threshold may deserve a bump to 120 Hz in a future cleanup. Out of scope for Session A.

### 4.2.1 Bug surfaced during §4.2 work (fixed in this commit)

While building `_multi_seed_summary`, the multi-seed gamma run reported
`"passed": {"mean": 1.0, ...}` while one of the three per-seed results was actually `False`.
Root cause: the benchmarks' `all_pass = oscillatory and has_oscillations and inh_faster`
expression short-circuits to `numpy.bool_(False)` when `oscillatory` is a numpy scalar
comparison. The numpy bool is not an instance of Python `bool`, so my `isinstance(v, bool)`
check in the summary skipped it, and `json.dump(default=str)` serialized it as the string
`"False"` downstream.

Two fixes in this commit:

1. All five `benchmark_*` functions now cast `"passed": bool(all_pass)` in their returns.
   JSON output is now canonical `true`/`false`, not string `"False"`.
2. `_multi_seed_summary` also accepts `np.bool_`, `np.integer`, `np.floating`, and the
   string forms `"True"`/`"False"` defensively for backward compat with any prior runs.

This is a minor correctness bug that would have silently under-counted failures in any
multi-seed sweep where *some* seeds fail. Surfaced exactly by the Session A work that's
supposed to catch it.

### 4.3 Homeostasis (5,000 neurons, 53 s sim)

The best-behaved benchmark of the three. All three phases (baseline / perturbation / recovery)
reproduce to within a few hundredths of a Hz across seeds. All 3 seeds pass.

| Seed | baseline (Hz) | perturb (Hz) | recov early (Hz) | recov late (Hz) | passed |
|------|---------------|--------------|------------------|-----------------|--------|
| 42   | 5.185         | 50.170       | 4.887            | 4.889           | ✓ |
| 43   | 5.210         | 49.992       | 4.909            | 4.895           | ✓ |
| 44   | 5.300         | 50.451       | 4.959            | 4.897           | ✓ |
| **mean** | **5.232** | **50.204**   | **4.918**        | **4.894**       | **3/3** |
| **std**  | 0.049     | 0.189        | 0.030            | **0.003**       |     |

Takeaway: `homeostasis` is the tightest regression target in the suite. `recovery_late` std is
0.003 Hz on a ~4.9 Hz mean — three parts in ten thousand. Any change that moves `recovery_late`
outside [4.88, 4.91] Hz is a real regression with near-zero false-positive risk.

Biology check: homeostatic adaptation target is `target_firing_rate_hz = 5.0 Hz` by default.
Recovery converges to ~4.89 Hz = 98% of target — biologically correct proportional control
behavior, and stable across realizations.

Key observation: within-seed reproducibility is now bit-exact. Cross-seed variance is high
for peak-frequency detection in gamma (28 Hz std) but low for firing rates and ratios
everywhere else (<2% of mean).

## 5. Known gap: `ou_seed` field is dead

`CoreSimConfig.ou_seed` (defined at `config.py:109`, exposed in the UI at `ui/layout.py:698`,
saved in every simulation profile) is **not consumed anywhere in `sim/bridge.py`**. The OU
process shares the main `cp.random` stream seeded by `_initialize_rng(cfg.seed)`.

Two options, deferred:

- **Option A — wire it up.** Add RNG-state save/restore around OU draws in `_run_one_simulation_step`,
  using `ou_seed` if provided. Cost: every step does a state swap, which has non-trivial overhead
  on cupy. Benefit: OU noise can be varied independently of heterogeneity / weight init.
- **Option B — remove the field.** Mark `ou_seed` as reserved, remove from UI and profile schemas.
  Cost: UI / profile migration. Benefit: stops lying about what the config controls.

Neither is urgent for the current work. Setting `seed` alone is sufficient for reproducibility,
and neither the biological benchmarks nor the research runners need independent OU seeds today.
Flagged for a future cleanup pass.

## 6. What's protected now

- **Reproducibility at a fixed seed.** Re-running `run_benchmarks.py -b gamma-oscillations`
  twice in a row gives bit-exact PSD output. Verified ✓
- **Drift across commits.** `tests/test_benchmark_drift.py` catches any change that shifts
  the seeded tiny-sim spike count by more than 10, or that breaks kernel-formula determinism.
  Locked baselines: tiny-sim = 170 spikes; gamma peak @ seed=42 in [25, 55] Hz. ✓
- **Cross-seed sensitivity is visible, not hidden.** `--multi-seed 42,43,44` reports
  mean/std/range. From §4: ei-balance std <1% of mean; homeostasis std <0.1% of mean;
  gamma peak-frequency std 28 Hz (expected — pre-existing metric-design issue, §4.2). ✓
- **Silent bool serialization bugs.** `bool(all_pass)` cast + `_multi_seed_summary` np.bool_
  handling. Surfaced during this work (§4.2.1). ✓

## 7. What's NOT protected

- **Cross-machine / cross-CuPy-version reproducibility.** CUDA reductions and some cuBLAS paths
  are not bit-deterministic across machines. The ±10 tolerance absorbs typical variation.
- **Concurrent-GPU effects.** If another process contends for the 3090 mid-run, timings vary,
  but numerical outputs do not (the simulation is synchronous per step).
- **`ou_seed` independence.** See §5.
