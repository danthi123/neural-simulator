## What the file names actually mean

Reverse-engineered from the data + the commit message of `ca291c2`:

- **`_sensedonly.json`** = the **flagship** config (perception arc Stage 1+2+3 + sensed reward, NO cross-projections). Confusingly named — "sensedonly" reads as "only sensed reward, no other cheats", but the data shows P0 finalQ=1.75 / P1 finalQ=1.63 which is consistent with the full perception arc, not a sensed-reward-alone ablation.
- **`_allnocheats.json`** = the flagship + `--bg-cross-projections` (the naive cheat-5 attempt). "All cheats closed including #5". Result sum ~8.4 across 3 seeds — the documented NEGATIVE result of the naive cross-projection attempt.

The commit message even calls this out:

> Cheat #5 (BG cross-projections) tested — broke phase-1 readaptation because phase-0 cortex_N/E activations reinforced cross-projections to all D1 pools, locking in N/E motor bias. 3-seed avg 8.40 (much worse). Kept opt-in but not in default config.

The 8.40 quoted here is exactly the average of the 3 `_allnocheats.json` files (9.00 + 7.20 + 9.00) / 3 = 8.40.

So the labels were swapped or misremembered when writing the finding doc — the FLAGSHIP numbers were filed under `_sensedonly.json` and the NEGATIVE cheat-5 numbers under `_allnocheats.json`.

## Why this happened

Most likely sequence: the autonomous session that committed `ca291c2` ran multiple validation configurations in parallel. When writing the finding, the author (Claude) read the stdout summary that listed sums by seed (which was correct for the flagship config) but hand-wrote the file paths to a guessed-pattern name (`_allnocheats`) without re-checking. The `_allnocheats.json` files actually committed were from the cross-projection negative test that was running concurrently.

This is the kind of drift that the new `sync-documentation` skill is designed to catch in the future — checking that finding docs reference files whose contents match the claims.
