## The boundary and the verified fix
rung-4 was GO at n_seq=2 but 0.000 at n_seq=8 (even n_cells=40 >> k_win*n_seq=32). The research gate proved (numpy isolation) the FLAT single-segment representation scales to n_seq=8 at ample cells (EMERGE-13 = 1.000), so the on-bridge failure was implementation-specific.

**Root cause (allocation churn — diagnosed by a trace, not guessed).** On the DENSE pre-allocated pool (p_init=0.0), the host winner/allocation logic decides reinforce-vs-allocate via `_match_count`, which required a CONNECTED synapse (`perm >= perm_conn = 0.5`) to count a "match". But a synapse only reaches 0.5 after ~4 potentiations (`lam_pot=0.14`). So for the first several epochs NO cell ever matched → the learner RE-ALLOCATED every epoch. With the `_committed_count` freshness metric saturating uniformly within ~1 epoch (every cell was a burst-winner at some point → equal counts → the `(count, index)` tiebreak collapses to INDEX ORDER), allocation became an index-order ROUND-ROBIN that ROTATED the context↔cell binding every epoch and never stabilized. At n_seq=2 the round-robin happened to keep 2 contexts disjoint; at n_seq>=3 (>2 contexts/epoch) the binding rotated and distinct contexts MERGED onto the same shared-middle cells → the branch columns learned nothing → branch 0.000. The trace showed epoch-0 allocation was perfectly disjoint (`[0-3],[4-7],...`) but by epoch 39 the contexts had collapsed. **The bridge WEIGHTED-coincidence prediction was proven CLEAN** (installing EMERGE-13's known-good connectivity into the EMERGE-14 pool → 1.000, zero over-firing) — ruling out a prediction/threshold bug and localizing the failure 100% to allocation.

**The fix (single variable, no `sim/` edit).** `_match_count` now thresholds a "match" at the COMMITTED level (`perm > p_init + 0.02`) — the SAME threshold `_committed_count` uses — instead of the CONNECTED level. A cell potentiated ONCE (`perm ~ 0.14 > 0.02`) counts as a match immediately, so re-training REINFORCES the epoch-0 disjoint allocation instead of re-drawing it — exactly the numpy FlatHTM oracle's behaviour (EMERGE-13 matches on potential-synapse `W>0` on its grow-from-zero pool). An untrained context (all `perm = 0.0`) still matches 0 → still allocates, so the no-teacher / untrained anti-cheats are preserved. Single-variable attribution proven: the identical harness with ONLY this threshold flipped gave conn=0.000 vs committed=1.000 (seeds 42/43/44).
