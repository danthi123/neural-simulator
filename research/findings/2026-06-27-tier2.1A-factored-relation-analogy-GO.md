## The mechanism (what was tested)

A:B::C:D on the FHRR phasor algebra (info in phase): bind = phase-ADD, unbind = phase-SUBTRACT, so
`T = B ⊗ A⁻¹` is the relation offset `(B − A)`, `apply(T, C) = (C + B − A)`, `D = cleanup(rec)`. This is the
phasor analogue of `king − man + woman = queen`. It is a **composition of the composer's already-validated ops**
— no new mechanism, no `sim/` edit.

**The decisive design (faithful + anti-cheatable + non-trivial).** Per the research gate (§1.2), simply storing
a relation slot and "unbinding it" would be a trivial-by-construction lookup that tests nothing. The genuine
test: every item is a point in a shared **factored attribute space**, and the analogy **EXTRACTS the transform
from the example pair (a,b) WITHOUT naming the relation**, then requires it to recover D for a **HELD-OUT** (c,d).
The relation living on an explicit factored axis is what makes `B−A ≈ D−C` hold:
- king = {GENDER:male, SEM:royal_hi}, queen = {GENDER:female, SEM:royal_hi} → `queen − king = female − male`;
- prince = {GENDER:male, SEM:royal_lo}, princess = {GENDER:female, SEM:royal_lo} → the SAME gender offset →
  `king:queen :: prince:?` recovers princess (the offset transfers to the held-out pair).

The item code = the **additive sum** of its per-attribute-value phasors (the `add` factored form). The transform
+ apply run through the composer's spiking `_bind` / conj synapse.

## The HONEST BOUNDARY — many-to-one relations (is_a / taxonomy) are NOT a clean offset

A taxonomy `is_a` relation (dog→mammal, cat→mammal, robin→bird) was tested and **fails** under additive factoring
(acc 0.167 < floor 0.333). The reason is structural, not a bug: `is_a` is **many-to-one**, so the per-item offset
`mammal − dog = GENERIC − i_dog` is **entity-specific** (`i_dog ≠ i_robin`), not a single shared offset. A clean
shared additive offset requires a **bijective** (one-to-one) relation. ⇒ factored-relation analogy serves
**bijective / parallel relations** (gender, capital_of, tense, comparative, antonym, …); **many-to-one relations
(is_a) need a set-membership / category-readout mechanism (a separate build), not a vector offset.** This is
recorded as the documented scope, not hidden — the production console deliberately ABSTAINS on `is_a` queries.
