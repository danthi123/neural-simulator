## TL;DR

The `unbind → transform → apply → cleanup` analogy **mechanism is sound on the composer's own spiking
ops** — but **only when the concept codes carry the relation as a clean additive phase offset.** The
composer's production fact representation (bundled role-filler binds) and its learned concept codes do
**not** have that structure, so analogy lands at **chance** on them.

| Representation (3 seeds, D=256, numpy) | analogy acc | memorization floor | lesion (skip unbind) | permuted-relation | moat (unknown→abstain) |
|---|---|---|---|---|---|
| **ADDITIVE** (clean relational phase codes) | **1.000** | 0.267 | 0.267 ↓ | 0.267 ↓ (=floor) | clean, 0 FA |
| **BUNDLED** (the composer's production `_bundle(_bind(...))` fact codes) | **0.000** | 0.267 | 0.333 | — | clean, 0 FA |
| **RANDOM** (no structure; the default per-seed codes) | **0.000** (chance) | — | — | — | clean |

- On ADDITIVE codes the analogy is real: acc **1.000 ≫ floor 0.267**; the **lesion collapses to the
  floor** (0.267) and the **permuted-relation control collapses to the floor** (0.267) — both anti-cheats
  fire correctly, so the transform is genuinely load-bearing there.
- On the production BUNDLED codes the same recipe is **0.000** — superposition cross-terms swamp the
  transform extraction `B ⊗ A⁻¹`.
- The production **learned codes** (`grounded_codes.npz`) carry *similarity* (cat–dog +0.426, bird–cat

⇒ analogy does NOT come for free from the existing composer codes. Shipping it would be the 2026-05-14

## The mechanism (what was tested)

Komer & Stewart 2020 (arXiv 2010.06746) / Rasmussen-Eliasmith SPA-RPM: the transform `T = unbind(B, A)`
captures the relation A→B; the answer is `D = cleanup(apply(T, C))`. On the FHRR phasor composer
(unit phasors, info in phase) this is exactly phase arithmetic realized by the bind/unbind synapses:

```
bind   = phase ADD       (diagonal complex synapse, role phasor)
unbind = phase SUBTRACT  (conjugate diagonal synapse)
T      = B ⊗ A⁻¹    →    T_phase = (B − A)
apply  = T ⊗ C      →    rec     = (C + B − A)
D      = argmax_w cos(rec, code_w)   over the codebook, excluding the operands {A,B,C}
```

This is the phasor analogue of word2vec's `king − man + woman = queen`. It is a **composition of the
composer's already-validated ops** — no new mechanism, no `sim/` edit. **Confirmed faithful through the
real RF spiking `_bind` op** (resonate-and-fire neurons + complex synapses, `_resonate`): the ADDITIVE
analogy scores **3/3 through `_bind`** (not just host phase arithmetic) — so the boundary is **purely
about code geometry, not the spiking substrate.** Analogy CAN run on the spikes; the codes just don't
carry the relation.

## The decisive diagnosis (why it fails on production codes)

A controlled three-way comparison isolates the cause (seed 42, D=256; identical across 42/43/44):

```
representation : analogy acc | memorization floor | lesion(skip unbind)
ADDITIVE    : acc=1.000  floor=0.600  lesion=0.400     # code = gender_phase + rank_phase
BUNDLED     : acc=0.000  floor=0.400  lesion=0.400     # code = _bundle(_bind(gender), _bind(rank))
RANDOM      : acc=0.000  floor=0.400  lesion=0.200     # code = rng.uniform (the composer default)
```

- **ADDITIVE** codes make `B − A` literally the gender-flip delta, so `C + (B − A)` recovers D exactly.
- **BUNDLED** is the composer's *actual* fact representation. `bundle()` (superposition) is not a clean
  group operation: `conj(bundle(X,Y)) ≠ bundle(conj X, conj Y)` in a way that isolates one component, so
  `B ⊗ A⁻¹` produces cross-terms whose dominant component is near-identity → the analogy returns C (or
  C's nearest neighbour), never the transformed D. (Symptom: the cleanup top-sim was **flat ~0.35 across
  every test** — a near-identity match, not a transformed one.)
- **RANDOM** codes (the per-seed default `rng.uniform`) have no shared relation → chance.

## The learned production codes lack the additive relational structure

`bridges/developed/month1/brain/grounded_codes.npz` (25 words, 128-D, learned from the developmental
corpus). They carry genuine **similarity** structure:

```
top similar pairs:  cat–dog +0.426 · bird–cat +0.408 · cat–mouse +0.355 · house–park +0.285 ...
```

But analogy needs **consistent second-order deltas** (`B − A ≈ D − C` across distinct pairs). Measured
over all 37,950 *disjoint* pair-pairs (no shared word, so a high value would mean a real shared relation,
not code reuse): **mean delta-alignment +0.0015, max +0.296 ≈ random.** The apparent +0.426 "aligned
deltas" in a naive scan are all `(cat,X)` vs `(dog,X)` — i.e. the `cat−dog` similarity reappearing, NOT
a transferable relation. So similarity ≠ analogy: the learned cortex gives first-order semantic
neighbourhoods but not the relational vector geometry. (This developmental vocab also has **no gold
analogy quadruples** — animals/objects/actions, no king:man::queen:woman style pairs — so there is
nothing to validate a production analogy against even if the geometry were there.)

## The anti-cheats (all fired correctly — this is how the NEGATIVE is trustworthy)

The FIRST control set was too weak and gave a false GO (acc 1.000) — exactly the 2026-05-14 trap. The
v1 test set let the answer be identified by **rank-similarity alone**, so the permuted-gender control
did NOT collapse (perm 0.967): the gender transform wasn't load-bearing on that test. **Sharpening the
candidate set so the transform is *necessary* to disambiguate** (each test pits D against a same-rank /
same-gender distractor that raw similarity-to-C would prefer) flipped BUNDLED/RANDOM to the true 0.000.
On ADDITIVE codes the sharpened controls behave exactly as a real result must:

- **(a) held-out ≫ floor:** acc 1.000 vs floor 0.267 (the C:D pair is never used to build the transform;
  operands excluded from cleanup). ✔
- **(b) permuted-relation collapses:** shuffle which value the relation maps to → acc 0.267 (= floor). ✔
- **(c) lesion collapses:** skip the unbind (T := B) → acc 0.267 (= floor). ✔
- **(d) moat holds:** an unknown token raises (abstains, 0 false-accepts) every seed; random-query cleanup
  sims (~0.06) sit far below correct-analogy sims (~0.35) so a confidence threshold cleanly separates. ✔

The controls prove the ADDITIVE win is real AND prove the production-code result (0.000) is a true
boundary, not a measurement artifact.

## Verdict & why I stopped

**NO-GO for a production `analogy()` on the existing composer.** The HARD GATE in the brief: *if held-out
≈ the lookup floor, OR permuted doesn't collapse, OR the moat breaks → STOP, write the honest NEGATIVE,
do not build further, do not over-claim.* The production-code held-out (0.000) is **below** the floor
(0.267) → gate fires NO-GO. I did not build a production analogy method and made no `sim/` edit.

**Precise boundary:** the analogy mechanism is correct and runs on the spiking substrate; what is missing
is **code geometry** — the production fact representation (bundled binds) and the learned concept codes do
not carry the additive/second-order relational structure that `B − A + C` requires. This is the same
family as the composer's documented "producing *meaningful* grounded codes is the open problem"
(`2026-06-06-composer-vsa-idealization-known-limitation.md`) and the "decorrelation is a red herring;
generalization needs the right learned geometry" thread (CYCLE 88–96).

## What would make analogy GO later (NOT built here — research-gated)

A future analogy capability needs a **representation whose relations are additive vectors**, learned, not
hand-built. Candidate paths (each its own de-risk):
1. **Learn relation vectors explicitly** — a small set of relation phasors `R_k` such that
   `bind(R_k, X) ≈ X-under-relation-k` (the SPA "structured concept" route the v2 test approximated by
   hand). Store concepts AS `bundle_k bind(role_k, value_k)` with relations factored out, then extract the
   transform from the *factored* codes (not the opaque concept code). Risk: the bundle cross-terms that
   killed BUNDLED here — needs a cleaner unbinding (e.g. an explicit relation slot, not superposition).
2. **A learned linear analogy map** over the PPMI code space (RLPFC-style relational integration) trained
   on relation exemplars — but the project's own evidence (`2026-06-16-onsubstrate-learned-binder-...`,
   the learned-linear-inverse NEGATIVE) warns a learned linear map is fragile here.
3. **A bigger/richer corpus** so the learned codes acquire real relational geometry (the owner's depth/
   breadth lever) — analogy may then emerge on the learned codes the way it does in large word2vec/GloVe.
   This is the most principled fix and orthogonal to the composer mechanism, which is ready when the codes are.

Per the standing research gate, any of these fires a deep-research review before building.
