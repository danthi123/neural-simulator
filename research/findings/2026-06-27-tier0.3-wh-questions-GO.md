## The mechanism (front-1 C1)

A wh-question is mechanically a **filler-gap dependency** — the *identical* WM-hold the embedded-clause scoping
already specifies. The fronted wh-word ("where/what/who") is the **filler** (held in WM — the dlPFC NMDA latch /
SAN-LAN syntactic working memory; Hagoort MUC Unification + on-line memory); the verb's stored **FRAME** (Tier 0.1,
`argstructure_composer.FRAME_ROLES`) says which argument slot is the **gap**; the wh-word selects which role to
query. "where does the boy go?" → wh=`where` → the GOAL gap (go's frame licenses GOAL, not LOCATION/patient) →
`query_role(agent=boy, action=go, role=GOAL)` → "park".

The wh→role **mapping** (the filler-gap lexicon) maps each wh-word to an ORDERED list of candidate roles; the
verb's frame CONSTRAINS which is gapped:

| wh-cue | candidate roles (frame-constrained) | example |
|---|---|---|
| `where` | GOAL · LOCATION | "where does the boy go?" → GOAL=park; "where does the dog put?" → LOCATION=table |
| `what` | patient · THEME | "what does the cat chase?" → patient=river; "what does the girl give?" → THEME=ball |
| `who` (subject) | agent | "who chase river?" → agent=cat |
| `who … to` (trailing PP) | RECIPIENT · agent | "who does the girl give to?" → RECIPIENT=dog |
| `whom` / `to whom` | RECIPIENT | — |
| `when` | TIME | (abstains on a verb whose frame has no TIME slot) |
| `where from` / `from where` | SOURCE | — |
| `with what` | INSTRUMENT | — |

The wh→role table is the host-side lexical scaffold (the dictionary, like the parser's morphology); the COGNITION
is the composer's spiking `query_role` on the resolved role.

## The cheap-first DE-RISK (HARD GATE) — `research/runners/_tier0_wh_questions_derisk.py`

Tiny vocab, numpy/CPU, 6 seeds (42–47). Stores 4 typed-role facts (boy-go-park GOAL; girl-give-ball-to-dog
THEME+RECIPIENT; dog-put-bone-on-table THEME+LOCATION; cat-chase-river default transitive) on the Tier-0.1
`ArgStructureComposer`, then asks natural wh-questions.

**Result: GO 6/6** (`research/findings/raw/_tier0_wh_questions_derisk.json`):
- **wh-answer all-correct** (7/7 every seed): where→GOAL/LOCATION, what→patient/THEME, who+to→RECIPIENT, bare
  subject who→agent.
- **the headline:** "where does the boy go?" → **"to the park"** (bare) / **"the boy goes to the park"** (full
  frame render, FrameCQ-ordered) — every seed.
- **moat:** 0 false-accepts total; **unanswerable** (boy+give has no GOAL, cat+go unstored) AND **frame-unlicensed**
  (when→TIME on `go` whose frame has no TIME slot) both ABSTAIN (return None) — abstain-all True.
- **VERIFY:** the rendered answer re-parses to the stored typed fact (content-mismatch would reject) — all True.
- **the LOAD-BEARING permuted-mapping anti-cheat:** a deranged wh→role table (where→patient, what→GOAL, who→THEME,
  who_to→THEME) reproduces **0** of the true answers, every seed — proving the wh→role MAPPING carries the meaning,
  not coincidence.
  - *(One subtlety found + fixed during the de-risk: the "who+to → RECIPIENT" resolution originally hard-wired
    RECIPIENT, bypassing the role table — so the permuted control couldn't derange it (reproduced 1 true answer).
    The fix routes the to-PP resolution THROUGH the role table under a distinct `who_to` key, so the anti-cheat
    bites that path too. This is exactly the [[feedback_spiking_structure_must_self_organize]]-style discipline:
    the meaning must flow through the mapping, not a hard-coded override.)*

## The BUILD (STEP 2) — production module + console route

### `research/runners/wh_question_parser.py` (new, composer-agnostic)
- `parse_wh_question(text)` → `{role, cue, agent, verb, form, wh}` (or None if not a wh-question). Two surface
  forms: auxiliary ("WH does AGENT VERB (PREP)?") and bare-subject ("WHO/WHAT VERB OBJECT?").
- `answer_wh(comp, text)` → `(filler, role, parse)`; `filler` is None on abstain (the moat).
- `bare_answer(role, filler)` → the short natural answer ("to the park").
- **COMPOSER-AGNOSTIC graceful fallback:** on a Tier-0.1 `ArgStructureComposer` (has `query_role` + the typed-role
  frame lexicon) the FULL filler-gap path runs (typed obliques GOAL/RECIPIENT/THEME/LOCATION/…); on the **deployed
  first-chat `RFPhasorComposer`** (only agent/action/patient) it falls back to `query_patient`/`query_agent`, so
  "who/what" questions still answer and a typed oblique (where→GOAL) gracefully ABSTAINS (no such role → honest
  non-answer, never a fabrication).

### `research/runners/first_chat_console.py` (ADDITIVE route)
- New `_wh_response(msg, wh_parse)` + a routing branch in `respond()`, sitting BEFORE the existing `_WHAT_DOES_RE`
  route. It fires for `where`/`when`/`who`/`whom`/`with-what` + bare-subject "who V P?" — the forms the rigid probe
  never covered. **"what does X V?" is deliberately LEFT to the existing route** (its rich discuss-while-answering
  is preserved) — the wh-route is purely ADDITIVE.
- A grounded answer renders the full frame sentence (Tier-0.1 render) + the short natural answer; an abstain
  returns an honest, topic-relevant non-fabrication (naming the agent's real PPMI neighbours, framed as
  association-not-fact — moat-safe by construction).
