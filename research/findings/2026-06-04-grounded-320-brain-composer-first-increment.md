# (A) grounded-320, first increment: the brain composer works on the REAL production 320-concept codes — 2026-06-04

**One line:** Direction (A) — grounded 320-concept brain agent — first cheap-first increment. The promoted
`CoreSimComposer` (the consolidated on-brain composer) runs at production vocabulary on the project's **actual
production 320-concept code scheme** (the G.20 sparse-distributed `generate_sparse_patterns`), not just the synthetic
codes of the prior vocab-robustness probe. Multi-seed (42/43/44): a 20-fact relational KB at V=320 holds
**what 20/20, who 20/20, abstain 20/20 every seed**.

## Context

The owner steered to direction (A) after the consolidation arc completed. The composer was already shown
vocab-robust to 320 on *synthetic* codes (`2026-06-04-core-composer-V320-vocab-robustness-confirmed.md`). The next
rung toward a *grounded* 320-concept brain agent is: does it hold on the project's **real production codes** — the
sparse-distributed scheme behind the shipped 320-concept ensemble — rather than codes I generated for the test?

## Method (`research/findings/raw/_core_composer_grounded320_probe.py`, GPU)

- Generate the 320 production codes with `generate_sparse_patterns(320, n_pool=2000, pattern_size=100, seed)` —
  the exact G.20 scheme (each concept = 100 random active neurons in a 2000-pool; expected pairwise overlap ~5).
- Convert each sparse pattern to a dense vector and project to the composer's dim (D=800) with a random Gaussian —
  **mirroring exactly how `load_concepts` treats the `denoise64` concept-pool activity** (the composer's native
  grounded-code path), then mean-center + unit-normalize.
- Feed via `CoreSimComposer(concepts=...)`, store a 20-fact KB with distinct (agent, action) cues, query each
  (who + what) and abstain on 20 never-stored cues.

## Result

| seed | between-cos (mean/max) | what (each patient) | who (each agent) | abstain (20 unstored) |
|---|---|---|---|---|
| 42 | 0.053 / 0.231 | 20/20 | 20/20 | 20/20 |
| 43 | 0.050 / 0.231 | 20/20 | 20/20 | 20/20 |
| 44 | 0.050 / 0.216 | 20/20 | 20/20 | 20/20 |

All three seeds: every fact in the 20-fact KB recalled correctly (who AND what) and every one of 20 never-stored
cues correctly abstained — perfect on the real production code scheme at 320-word vocabulary.

The projected production codes are well-decorrelated (between-cos ~0.05) — sparse random patterns have low
expected overlap by design, so this is a benign regime. Combined with the ρ=0.6 synthetic stress test (which also
held), the composer is now bracketed at **both** ends: the production code statistics (cos ~0.05) and a hard
correlated stress (cos ~0.60).

## Rung 2: the FULL agent at V=320 (parser + composer, end-to-end)

The result above validates the composer. Rung 2 lifts the **full `BrainConversationalAgent`** to 320: a `concepts=`
passthrough was added to the agent constructor (the parser is vocabulary-agnostic — it assigns roles by word
position × voice — so the same trained parser serves any vocabulary). The agent is built with the production 320
codes, then driven through its own API: `hear()` comprehends each 3-word SVO sentence via the spiking parser and
stores it in the composer; `what_does`/`who_does` query; abstain on the unknown.

|---|---|---|---|
| 42 | 12/12 | 12/12 | 12/12 |

Multi-seed: the complete conversational agent comprehends and stores each sentence through the parser, recalls who
and what, and abstains on the unknown — all at 320-word production vocabulary, all spiking on the core sim. The
parser's position→role comprehension is confirmed **vocabulary-agnostic at production scale**.
(`research/findings/raw/_brain_agent_grounded320_s{42,43,44}.json`.)

## Honest scope (what this is and isn't)

- **Is:** the brain composer (spiking bind/unbind + cleanup + no-confab moat) operating at 320-word production vocab
  on the **real production code scheme**, with a 20-fact relational memory, multi-seed. The first concrete step of
  direction (A).
- **Isn't (yet):** the production codes are fed *as data* (generated by `generate_sparse_patterns` + projected) —
  they are the production *scheme* but not *captured from a running 320-concept-pool bridge*. The heavier, fully
  grounded rung is to capture 320 concept-pool activities from a sparse-distributed shared-pool bridge so the codes
  are the substrate's **own** (as `denoise64` is at V=16). Rung 2 covers comprehension (parser) + flat fact memory
  + who/what + abstention through the full agent; the **dialogue-planning** path (`elaborate`) and the
  **composition-depth** categories (two-attribute, embedded clauses) at 320 vocabulary are the next checks (the
  capacity-curve finding notes composition-depth categories need D to grow with vocabulary, so a boundary there
  would be expected and honest).
