# Tier 2.1 v1+v2 — synonym binding shows asymmetric WTA failure mode

**Date:** 2026-05-06 ~02:15 EDT
**Status:** v1 (200 events/action, 100/synonym) and v2 (400/action,
200/synonym) both fail W→A permuted-label. A→W aligns at GROUP
level. Pattern points to STDP winner-take-all asymmetry. v3 with
synonym co-firing now launched.

## Diagnosis: STDP winner-take-all per synapse

Per-motor A→W confusion pattern (v2):

```
motor_N → {north: 17, up: 0, ...}    -- 'up' completely absent
motor_E → {north: 14, east: 7, up: 1, right: 1, ...}
motor_S → {north: 12, south: 4, up: 1, right: 5, left: 2, ...}
motor_W → {north: 8, west: 5, up: 0, right: 3, left: 3, ...}
```

The PRIMARY synonym ("north") for each pair gets predicted; the
SECONDARY synonym ("up", "right", "down", "left") gets ~0
predictions across ALL motors. Total "up" predictions across 100
A→W trials: 1.

This is **STDP winner-take-all at the synapse level.** When motor_N
fires during training, lang_input → motor_N synapses see EITHER
"north" code or "up" code per trial (50/50). One pattern accumulates
slightly more co-firing first; STDP locks in to that pattern;
secondary patterns can't compete.

Tier 1 worked because each motor saw ONE input pattern (no
competition). Tier 2.1 introduces two competing patterns per motor,
and STDP picks one.

## Asymmetric direction failure

W→A direction (input → motor) FAILS: when "up" is presented (not
the consolidated "north"), motor_N doesn't reliably activate. The
motor pool's input-side STDP locked in to "north"-pattern neurons;
"up"-pattern neurons have weaker → motor connections.

A→W direction (motor → output) WORKS at group level: motor_N reliably
activates language_output region with patterns near "north". STDP
on motor → output collapsed both training presentations into a single
output cluster. "Up" pattern doesn't get produced (different cluster),
but the GROUP {north, up} is mapped correctly.

So: **A→W binds the synonym pair via output collapse. W→A requires
both input patterns to reach the motor pool, which they don't.**

## Cofire fallback (now running as v3)

Hypothesis: presenting BOTH synonyms simultaneously during 30% of
trials forces input-side Hebbian co-firing between "north" and "up"
neurons. After ~480 cofire trials (30% × 1600), the two codes share
representation. When either is presented alone, both code's neurons
partially activate → motor_N receives the same input as before
either way.

v3: `--synonym-mode --synonym-cofire-fraction 0.3 --n-events-per-direction 400`

ETA ~50 min single seed.

## If v3 also fails: v4 = scale up architecture

User reminded me of VRAM headroom (24GB available, current 1.6GB
used). v4 option:
- n_lang_input: 2048 → 4096 (more capacity per code)
- n_motor_per_action: 500 → 1000 (room for sub-populations within action)
- n_lang_output: 2048 → 4096 (richer output cluster)

Hypothesis: with 1000-neuron motor pools, each can develop two
functional sub-clusters — one for each synonym — within the same
action. STDP doesn't have to compete; both consolidate.

Cost: ~2x compute. Memory ~6GB. Still fits.

## What we've learned about the embodied paradigm

1. **Tier 1 (4 words, no synonyms)** works robustly at biology canon
   with ~200 trials/word.
2. **STDP at synapses is winner-take-all** when multiple input codes
   compete for the same target. Tier 2.1 v1/v2 demonstrates this.
3. **Output direction is more forgiving** — collapses input variation
   into a single cluster.
4. **Forward direction (input → motor) is the bottleneck** for
   synonym binding. Cofire trick or scaled-up architecture should
   address it.
5. **The mechanism doesn't trivially extend** to richer vocabularies.
   Each scaling step (4→8 words, 8→16, etc.) likely needs a specific
   intervention.
