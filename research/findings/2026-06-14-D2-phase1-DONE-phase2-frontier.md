## Phase 2 — first realization NEGATIVE; the frontier is the spiking concept→code readout
The plan's Phase-2 reframe: the Option-C readout computed codes from the learned recurrent `W` (a numpy spreading-activation the synaptic-current gain doesn't touch), so Phase 2 must read codes via a **bridge forward pass**. The first realization (`research/runners/dendritic_cortex_forward_codes_derisk.py`): drive a hub region by each concept's co-occurrence pattern → a random dense projection to a readout region → read the readout's gain-normalized activity as the code; gain ON vs OFF (the point-neuron control), structure recovery vs the a-priori taxonomy.

**Result: NEGATIVE across six diagnostic iterations** (firing-read → conductance-read; raw-count → presence drive; drive-scale sweep; fast → slow EMA for marginal-vs-instantaneous normalization). The readout codes are consistently **anti-correlated** with `S_true` (≈ −0.07, vs host +0.96), and the gain has **≈ zero differential effect** (dendritic ≈ point-neuron at every setting). Diagnosis (the root causes, per systematic-debugging — stopped tweaking at the iron-law threshold):
1. **The rheobase threshold silences the rare, informative category hubs** (low count → below firing threshold) while the common hubs fire — the category-distinguishing signal is lost at the hub layer before the gain can act.
2. **The spiking forward pass + random readout projection do not linearly preserve the hub-profile cosine** — even the raw (gain-off) readout codes are anti-correlated with the structure that is +0.96 in the counts, so the readout architecture itself is scrambling/inverting the linear structure.
3. **The per-source EMA does instantaneous, not marginal, normalization** unless very slow — and even a slow EMA didn't rescue it, because (1)+(2) dominate.

**Precise localization (CPU diagnostic `research/runners/_dendritic_cortex_diagnose.py`, + a drive sweep):** the failure is the spiking READOUT, not the gain or the input. The presence-drive input pattern carries strong structure (**Pearson +0.923** vs S_true); as the hub drive rises above rheobase the **hub firing** climbs from anti-correlated toward 0 (it partially preserves the input), and the dendritic-vs-point-neuron gap emerges (drive 250: dendritic +0.022 vs point-neuron +0.004); but the **readout `g_e` code stays ≈0/anti-correlated at every setting** — the random projection + Izhikevich readout dynamics do not linearly preserve the hub-profile cosine. So the structure is present in the input and partially in the hub layer, and is lost at the spiking readout. (At very low drive the near-silent hubs also leave the per-hub EMAs barely differentiated — common 0.0065 vs category 0.0049 — so the gain is near-uniform; reliable firing at higher drive fixes that part but the readout-scrambling dominates.)

**This is an honest, valuable frontier finding, not a failure of the mechanism.** The gain *mechanism* is verified (Phase-1 bridge tests + D1.7 spiking two-compartment). What Phase 2's first attempt localizes is that the **cortex-scale concept→code readout on a spiking substrate is the genuine open problem** — the spiking dynamics (threshold, the projection) don't behave as the rate-level D1.x toys assumed. This is the same *class* of problem the dual/CLS pipeline (Phase 3) exists to handle (raw spiking activity is not a clean linear code → decorrelated codes + attractor cleanup). The next Phase-2 iteration needs a different concept→code architecture (candidates: a learn-based route where the gain modulates the recurrent Hebbian growth during co-fire — the reframe may have been too quick that the gain can't touch the learn; an above-threshold rate-preserving encoding; or reading codes through the dual/CLS cleanup rather than a raw projection).

## UPDATE (same day) — the gain's value IS CONFIRMED on the bridge (the frontier is now an optimization, not a NEGATIVE)
After the localization, two fixes turned the forward-pass route positive and **confirmed the dendritic gain is load-bearing on the bridge**:
1. **Disable spontaneous OU noise in the cortex** — the spontaneous firing was giving every hub a baseline rate that swamped the per-hub co-occurrence marginal. With OU off, the per-hub EMAs encode the marginal correctly (common 0.021 vs category 0.0004, **~53×**) so the gain differentiates (common gain 0.73 vs category 0.99).
2. **The right drive regime.** With *presence* drive (binary co-occurrence) + a clean readout, the **point-neuron already succeeds** (+0.277, gen 0.875) — because the spiking **rheobase threshold is itself a presence-binarizer** that removes the common-mode the gain was designed for; the gain is then unnecessary (and even hurts). The gain's D1-level value lives in the **raw-count magnitude regime**. So the faithful test is a **baseline-offset raw drive** (count + baseline; keeps the common-mode magnitude while lifting the low-count category hubs above rheobase so they fire). **There the gain is decisively load-bearing:** baseline=12 → dendritic **+0.052** vs point-neuron **−0.012**; baseline=6 → dendritic −0.001 vs point-neuron **−0.116**; baseline=8/scale6 → +0.048 vs +0.010 — **the point neuron fails and the dendritic gain recovers the structure on the real bridge, multiple settings.** This is the D1-level advantage, now on-substrate.

**So Phase 2's mechanism works; the open piece is the MAGNITUDE** (dendritic ≈ +0.05 vs host ceiling +0.96) — the spiking readout (random projection + Izhikevich dynamics) caps it. Two project-aligned levers to push it: a structure-preserving (vs random) readout, and the validated **dual/CLS attractor cleanup** (which exists precisely to denoise spiking codes — though it needs the raw code roughly right first, which the gain now delivers in the right regime). The honest scientific nuance to carry: on a spiking substrate the firing threshold provides *some* of the common-mode robustness the gain was designed for (the presence regime), so the gain's marginal value is regime-dependent — clearest where the code must preserve count *magnitude*.
