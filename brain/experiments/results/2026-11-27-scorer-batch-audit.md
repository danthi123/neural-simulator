## Verdict in one paragraph
The Lift-Gate-Glue mechanism (padded, batched bf16 top-1 on near-ties) cannot occur here in its original form: the cortex is a recurrent RWKV-7 run ONE sequence at a time, there is no batch dimension, no padding, no attention mask, no bf16 (cuda fp16 or cpu fp32, optional cuda fp32). Every scorer in scope reads one prompt per call. The same class of failure DOES exist in three other forms, none of which is a batch effect: (1) arms of one comparison can be routed through two different forward implementations (RWKV package vs PlasticCortex); (2) device/precision is not enforced or even recorded correctly in the experiment scripts, so a resumed or pool-split run can mix devices inside one comparison; (3) replies are nucleus-sampled (top_p 0.3) from a paired RNG, so any logit perturbation can flip a reply, and the repro gates (not the numerics) are the only protection. Nothing found is a live confound in a finished verdict. For FUTURE runs (not the running test2 or the running memory_ceiling), F1 (hypothesis, to be measured) and F2 should be addressed before a later AWS fp16 batch is read.

## What is shared (no batching anywhere)
- `brain/cortex.py:76-79` `Cortex.read` encodes ONE string and calls `forward` once (state deep-copied). `:94-97` `forward`. `:99-131` `speak` is token-at-a-time (T=1 forward at `:129`), argmax only when `temperature <= 0` (`:117`, never the default); the default is `pipe.sample_logits(top_p=0.3)` (`:118`). No `pad`, `batch`, `forward_batch`, `stack`-of-prompts exists in `brain/` (grep of forward/full_output/stack/pad/batch: every `torch.stack` is over stored keys/residuals, never over prompts).
- Package forward (`.venv/.../rwkv/model.py:1473`): `seq_mode = len(tokens) > 1` selects the GEMM sequence path vs the one-token GEMV path, and `:1665` `x[-1,:]` slices BEFORE the head unless `full_output`. This is the only "shape" dependence: sequence length T and last-vs-full output change which kernel computes the head. It is the RWKV analogue of batch-shape numerics, and it is identical for every arm that reads the same text.
- Strategy: `cortex.py:65` cpu fp32 | cuda fp16 (default) | cuda fp32 (`--cuda-precision fp32`, also turns TF32 off `:68-72`). TF32 is otherwise ON process-wide on cuda (rwkv/model.py:11-12, 179-180).

## Findings

### F1. Arms of one comparison run through two different forward implementations (MEDIUM on cuda fp16, LOW on cpu)
`LiveCortex.active` (`brain.py:151-153`) is `_changed and consolidated_on`. Active: `PlasticCortex.forward` (fp32 activations, per-token python WKV loop, `plastic_cortex.py:70-80`, full head then `logits[-1]`). Inactive: the rwkv package forward (fp16 on cuda, JIT kernels, `x[-1]` before the head). `set_lesions` (`brain.py:870-873`) flips it per arm, `ARMS` (`life.py:51-52`) uses it for consolidated-off and both-off, `hear` flips it per turn for unfamiliar cues (`brain.py:614-615`, `:638`), and a never-slept (nosleep line, `life.py:1084`) cortex is always raw. So these comparisons subtract two numerically different pipelines:
- `g_minus_null(off, null)` (`life.py:745`) and the savings read: hippocampus-off (plastic) minus both-off (raw), on `option_lp` log-odds.
- intact vs consolidated-off reply rates; slept lines vs L-nosleep.
HYPOTHESES, none measured here: (H1) on CPU both sides are fp32 and the gap is small, guessed at order 1e-5 (asserted, not measured). (H2) On cuda fp16 the raw side rounds activations to fp16 while the plastic side runs fp32 activations on fp16-rounded weights, guessed at order 1e-2 in logit gaps (asserted, not measured). (H3) TF32 matmuls contribute on the plastic side (inferred from rwkv/model.py:11-12 and :179-180 being on by default; not verified for this path). (H4) 'Collapse guard flips' between cpu and cuda B in the 11-23 note are a device effect of this size and kind: unverified, that note shows a device effect on guards but does not attribute it to this raw-vs-plastic difference. The measurement that would settle H1-H4 is the paired read described below.
Not an issue for B vs K-P vs PR (all slept, all plastic) or for any contrast made entirely inside the plastic path (TAG vs SHAM vs LESION in voice_tag/oracle, adapters on/off on one PlasticCortex).
Fix only where it can bite (FUTURE runs only; the running test2 is frozen and unaffected by this note): for later AWS g5 test2 reads, treat consolidated-off, both-off and nosleep contrasts as DEVICE-SENSITIVE (report them but do not let a verdict hinge on a sub-0.1 margin), or run the AWS lives with `--cuda-precision fp32` (matches CPU numerics, `cortex.py:61-72`), or route the inactive branch through `PlasticCortex(enabled=False)` for scoring reads. The cheapest check is a one-off paired read of the same 30 prompts through raw vs `PlasticCortex(enabled=False)` on one g5, comparing top-1 and top-p-set equality; I did not run it (no model runs allowed).

### F2. Device/precision is not enforced or correctly recorded in the experiment scripts (MEDIUM, provenance)
- `Cortex` has no `.device` attribute (`cortex.py:57-74`), so `getattr(cortex, "device", ...)` records "?" in `memory_ceiling.py:371`, `cascade_screen.py:123`, `voice_split.py:92` and the constant "cpu" in `voice_tag.py:188` and `voice_ceiling_oracle.py:386`, whatever device was used. The true value lives in `cortex.strategy` ("cpu fp32", "cuda fp16", "cuda fp32").
- `memory_ceiling.run` resume and `score` reject mixed commit and stage0 sha (`:382`, `:397`, `:558-562`) but accept units from different devices, precisions or hosts. A resume of a pool unit on a different `--device` would put two arms of one (seed, night) on different numerics, undetected.
- `life.run` resume (`:1000-1020`) re-checks brain_kw flags but not `device`/`strategy` against the saved life; `life_bars.py` pools six lives without a device check (only `life_compare.py:32` has one, for arm-vs-B).
- `local_sleep.result_header` (`:187-195`) does not write the device.
Fix (small, scripts only, does not change numbers): record `strategy` from `cortex.strategy` in those headers; in `memory_ceiling.run` refuse a unit file whose recorded strategy differs; in `life.run` resume refuse a device/strategy change; have `life_bars` print a warning when the six lives disagree on `provenance.cuda_precision`/`device`. Applied only to the three experiment scripts listed under Status (header recording). Everything else in this list is a proposal for future runs: `memory_ceiling.py` and `local_sleep.py` are in use by running pool jobs, and `life*.py` is frozen for the running test2. Also check in `memory_ceiling.run` that the replay strategy equals the banked life's `res["provenance"]["cuda_precision"]` (the banked A arm must reproduce).

### F3. Sampled replies make every reply-level comparison a near-tie scorer (informational, LOW)
`speak` samples with `sample_logits(top_p=0.3)` (`cortex.py:118`; rwkv `utils.py:55-75`: nucleus cutoff at the first cumulative prob >= 0.3, `np.random.choice` on cpu, `torch.multinomial` on cuda). Paired seeds (`_reseed(seed, 500+night)`: `life.py:112-116`, called before each probe/arm and each question in the voice scripts) fix the uniform draws, but a logit perturbation of 1e-5 can move a token across the cumulative-0.3 cutoff or across the draw's CDF boundary, changing the candidate set; the reply then diverges and, because `hear` carries state, so does the rest of the battery. This is the real near-tie channel here, and it is why: CPU and cuda replies can never be compared one-to-one (different RNG backend, `np.random` vs `torch`), and any two arms that differ at all will differ in some replies. Protections that exist and work: the void/reproduction gates (routing_replay void rows, voice_ceiling_oracle `repro_ok`, memory_ceiling A vs banked). No fix needed; keep reply-level claims at the pooled-rate level with CIs, as the preregs already do.

### F4. memory_ceiling A-arm reproduction is reported, not gated (LOW-MEDIUM; REPORT-ONLY for the run now in progress)
`reproduces_banked` (`memory_ceiling.py:360`, `:569`) is printed but not a verdict check (`verdict` `:479-519` has no such clause). If the replay runs on a different device/precision than the banked KR lives, arm A silently diverges from banked and the ORACLE-A and OFF-A pairs are computed from replies that no longer match the lives that fixed the stage-0 decisions. Fix: add a check `A reproduces banked >= REPRO_MIN` (the same 0.9-style gate as `voice_ceiling_oracle.repro_ok` `:371-375`) as a registered INCONCLUSIVE condition, or at least print it next to the verdict as a hard warning. For the memory_ceiling run now in progress this is report-only: `reproduces_banked` is computed and printed but is NOT a verdict clause, so the in-progress verdict cannot be voided by it. Read the printed `reproduces_banked` next to the verdict by hand when the run lands; if it is low, treat the verdict as unreliable. Adding the gate needs the prereg owner's wording and applies to the next launch, not this one; no file was edited.

### Checked and clean
- No arm of any audited comparison runs at a different batch shape: nothing is batched. T-dependence is identical across arms because each arm reads the same prompt text (`f"User: {q}\n\n{b._asst}"`) in the same chunking. The one place chunking varies by flag is `commit_exchange` (`brain.py:672-713`: one read vs head/reply split vs `arousal_gain` split with `read_nll`), which is a method difference between arms of the arousal/own_gain/own_decay experiments (not in the audited list); on cpu the effect is fp32 noise, on cuda fp16 treat as F1-sized.
- `voice_ceiling_oracle`: adapters, device, thread count, and path identical for all arms; `REQUIRE_ACTIVE` makes a silent path switch impossible.
- `voice_tag`: the primary contrasts (TAG, SHAM, LESION vs A0) use adapters re-slept on the same host; only A0snap (banked on another device) differs, and it is a labelled reproduction arm, not a primary contrast.
- `routing_replay`/`memory_ceiling` decisions: one cue read feeds every arm's decision, so arms cannot disagree through different cue numerics.
- `sleep_probe`/`local_sleep`: greedy, single prompt, all arms through one PlasticCortex in one process.
