Status: PLAN. The 1.5B result is provisional (3 seeds). Source: `research/cortex-size-1103b`,
`brain/experiments/results/2026-11-03-cortex-size/2026-11-03-cortex-size.md`: sleep recall (hippocampus off) at

Code read: `brain/{brain,cortex,chat,plastic_cortex,hippocampus,sleep}.py`, `brain/eval/weekly.py` on main, and

## Measured today (CPU only, shapes read from the checkpoints with mmap; no GPU used)
| | 0.1B | 0.4B | 1.5B |
|---|---|---|---|
| layers / width / heads x 64 | 12 / 768 / 12 | 24 / 1024 / 16 | 24 / 2048 / 32 |
| matrix memory per layer (floats) | 49,152 | 65,536 | 131,072 |
| one episode (fp16 deltas, all layers + fp32 key) | 1.3 MiB | 3.3 MiB | **6.5 MiB** |
| live state (fp32) | 2.3 MiB | 6.2 MiB | 12.4 MiB |
| rank-8 adapters (ffn key+value) | 0.74 M / 2.8 MiB | 1.97 M / 7.5 MiB | **3.93 M / 15 MiB** (+Adam ~45 MiB in sleep) |
| weights fp16 / fp32 | 0.36 / 0.71 GiB | 0.84 / 1.7 GiB | **2.85 / 5.7 GiB** |
| CPU decode, fp32, 4 threads (machine loaded) | 16 ms/tok | - | **131 ms/tok** (load 3 s) |

Reply latency (a turn = cue read + prompt read + ~30-120 spoken tokens + read-back):
- CPU 1.5B: ~5 s for a 30-token reply, ~16 s at the 120-token cap (more threads: perhaps 2x faster).
- 3090 fp16 (estimate, not measured: the rwkv package's per-token step is launch-bound, ~24 layers):
  ~25-40 ms/tok -> ~1-2 s per turn. Measure it in step 4 below; do not quote this as a result.
- After the first sleep, LiveCortex speaks through PlasticCortex's Python per-token loop in fp32 with a full fp32 copy
  of the weights: slower than the package and **8.5 GiB resident at 1.5B** (2.85 fp16 raw + 5.7 fp32 copy). Fix below.

Memory growth: at 6.5 MiB/episode, 100 stored tellings = 650 MiB, 1,000 = 6.5 GiB. Episodes stay on the cortex's
device (`Hippocampus.store` keeps `delta` where it was made, i.e. VRAM on cuda), and `chat.py` rewrites the whole
`memory.pt` after every turn. Both are fine at 0.1B for the weekly test (~10 episodes) and wrong for a lived life at 1.5B.

## VRAM sharing and the reference-hardware rule
- Rule: the BRAIN must run on one 3090-class GPU. 1.5B does: inference ~3-4 GiB after the merge fix, sleep ~17 GiB own.
  The local LLM (`tools/local_llm`, ~21 GB loaded) is driver infrastructure, not the brain; it is time-shared, never
  co-resident with sleep (17 + 21 > 24). Co-residence for chat is also out (21 + 2.6 desktop + 3.5 > 24).
- So: the brain gets the card by **yielding the LLM**, never by squeezing. Interactive chat: `llm off` (or wait for its
  15-min idle unload) then `--device cuda`; if the LLM is busy, chat on CPU (5-16 s/turn, 5.7 GiB RAM, no sleep).
- Sleep is a GPU job only (CPU fp32 sleep at 1.5B: ~17-20 GB RAM and an estimated hour+; not a path).

## When sleep runs
- Today (integration branch) sleep runs inside `Brain.__init__` / `close()` (restart = night). At 1.5B that is a
  ~10-min blocking start that needs 17 GiB free: unacceptable for chat startup and impossible while the LLM is loaded.
- Change: keep "restart = night" as the semantics, but run the night as its own process: `python -m brain.night
  --home DIR --device cuda` (load, `pending()` -> `sleep()` -> save adapters, log `torch.cuda.max_memory_allocated`,
  exit), queued through `tools/gpu_queue.sh` wrapped in `tools/local_llm/llm.sh run` (unload LLM, run, reload).
  Nightly at a fixed hour via the existing timer machinery, plus once on demand after a chat session closes.
  Chat runs with `sleep_on_restart=False`; a lock file in the home stops chat and night touching one brain at once.
- A chat started with pending episodes and no night yet simply speaks with yesterday's synapses (the hippocampus still
  holds today's facts). Nothing is lost by a delayed night.

## Weekly test runtime
- Integration weekly: two arms, both sleep at the session-1 -> session-2 restart. At 1.5B / 480 steps on the 3090:
  2 x ~10 min sleep + 32 turns x ~1.5 s + load = **~25 min**, GPU required, LLM yielded. On CPU it is not feasible.
- Halve it: both arms sleep identically (same seed, same episodes), so sleep once and copy the home (adapters) for the
  lesion arm. Then ~13 min. Hermes (which IS the local LLM) cannot run it in-process: Hermes queues
  `llm run python -m brain.eval.weekly --device cuda --model <1.5B>` and reads the transcript when it lands.

## Ordered checklist
1. **Six seeds first** (gate for everything below): `sleep_probe --device cuda --model <1.5B pth> --lr 5e-4 --steps 480
   --kl-weight 3 --seed {100,101,102}` via gpu_queue + `llm yield`, ~90 min. Log a real VRAM peak (max_memory_allocated).
2. Apply the decision rule (below). Steps 3-11 are model-agnostic and worth doing for 0.4B as well.
3. Model is config, not a default: `--model` on `chat.py`, `weekly.py`, `brain.night`; `Brain` records
   `meta["cortex_model"]` and refuses to load a home made with another cortex (deltas and adapters do not transfer).
4. Merge adapters into the package weights for speech: ffn key/value are linear before/after the relu, so
   `K' = K + A_k B_k`, `V' = V + A_v B_v` exactly; write them into `cortex.model.z` (fp16) after each night, keep the
   pristine ffn weights on CPU (~1.5 GiB at 1.5B) for the consolidated-off lesion and `cue_response`. Drop the
   resident fp32 PlasticCortex outside sleep. Test: merged logits == LiveCortex logits (fp16 tolerance) on 0.1B.
   Then measure 3090 ms/token at 1.5B (one short gpu_queue job) and replace the estimate above.
5. Hippocampus storage: `delta` to CPU at store, moved to the device only in `reinstate`; keys stay small (0.5 MiB at
   1.5B, could shrink further). Save episodes as one file each (append), not a full `memory.pt` rewrite per turn.
6. Forgetting bound (owner: forgetting is fine): after a night, episodes whose effective strength fell below a floor
   and that sleep has consolidated may be dropped from the hippocampus (not permanent ones). Cap = disk, not VRAM.
7. `brain.night` entry point + lock + gpu_queue/`llm run` wrapper; nightly timer; chat uses `sleep_on_restart=False`.
8. Sleep defaults per model: 1.5B lr 5e-4 / 480 / kl 3, rank 8 (0.4B: lr 1e-3 / 480 / kl 3). One table in `brain.py`
   keyed by `cortex_model`; no silent 0.1B values (integration default is 240 / 5e-4 / kl 1).
9. Re-fit the thresholds that were fitted at 0.1B, on the fitting set only: `Hippocampus.GAIN` (scale ladder at 1.5B:
   4.0 -> 10/12 reinstated, fine), `FAMILIARITY`, `FAMILIARITY_SPONTANEOUS`, `MARGIN`, `KNOW_BAR_HIPPOCAMPUS/_CORTEX`.
   Watch selection by paraphrase: 5/12 at 1.5B vs 8/12 at 0.1B (scale ladder): a known weakness to carry, not a new one.
10. Migration of the live home: deltas and adapters are cortex-specific. Re-encode stored episodes by reading their
    `text` through the new cortex at the same `base` (one-time transplant, declared in `SCAFFOLDS.md`), keep
    strength/uses/permanent, discard adapters, run one night. The 0.1B home stays as an archive.
11. Weekly: `--model`, cuda, single shared sleep for both arms, wrapped in `llm run`; first 1.5B transcript lands as
    the weekly record with the model named in its header. Tests: `tests/test_brain_sleep.py` and the 0.1B golden
    fixture stay 0.1B on CPU (CI stays light); add a shape-only test that 1.5B-sized deltas live on CPU.
12. Update `brain/ARCHITECTURE.md` (cortex size), `HANDOFF.md`, `research/coordination/PI_LANE.md` (Hermes weekly
    command), and land via land-result.

## Decision rule (six-seed bar)
Run 1.5B at lr 5e-4 / 480 / kl 3 on all six seeds (42/43/44 done, 100/101/102 to run). ADOPT 1.5B only if all hold:
- true-replay recall > shuffled and > no-sleep on **every** seed;
- six-seed mean true recall **> 4.0/12** (0.4B's six-seed mean) and 1.5B >= 0.4B on at least 4 of 6 paired seeds;
- false recall mean <= 2.0/4 (0.4B's) and drift gKL < 0.05 on every seed (no divergence);
- logged sleep peak <= 21 GiB on the card (leaves the desktop its share of 24 GB).
Otherwise **0.4B stays**. Lr is not re-tuned per seed after seeing the six (that would be selection on the test).

## Reverse plan (1.5B not confirmed)
- Default cortex = 0.4B at lr 1e-3 / 480 / kl 3 (already six seeds). Steps 3-11 still land; they are size-agnostic.
  At 0.4B: episodes 3.3 MiB, inference ~1 GiB VRAM (could even co-reside with the LLM: 21 + 2.6 + 1 = 24.6, too tight;
  still yield), sleep ~half the 1.5B time, CPU chat ~3-4x faster than 1.5B.
- Keep the 1.5B result as a lead; revisit when sleep tuning (replay content, steps, rank) raises 0.4B's gap to its
  11/12 ceiling or not. A loss at 1.5B is a verdict on this sleep setting, not on scale.
- If the live home was already migrated to 1.5B: re-encode back from `text` the same way (step 10) and sleep once.
